# CollegePortal

Информационная система колледжа искусств: приёмная комиссия, контингент, учебные планы, нагрузка, расписание, электронный журнал, кадры, проходная по QR, отчёты, подготовка данных для ФИС ГИА и ФРДО.

Стек: Laravel 12 / PHP 8.4 / PostgreSQL 17 / Redis на бэкенде, Vue 3 + Vite + Pinia + Quasar на фронтенде, Docker Compose и Nginx в развёртывании.

## Язык

Ответы пользователю, планы, отчёты, документация и любой текст интерфейса — на русском. Английский только для неизменяемых технических идентификаторов: команды, пути, URL, endpoints, имена классов и переменных, ветки и сообщения коммитов.

## Главное, что нужно знать до начала работы

**На рабочей станции Windows нет инструментов разработки.** Ни `php`, ни `node`, ни `npm`, ни `docker`, ни `composer`. Есть только `git`, `ssh` и VS Code. Не пытайтесь запускать здесь тесты или сборку — это не поломка, так устроено рабочее место.

Вся сборка и все проверки выполняются **на DEV-сервере по SSH**.

## Как запускать проверки

Всё выполняется в контейнере на DEV. Рабочее дерево DEV трогать не нужно — создавайте отдельный worktree.

```bash
# на DEV
cd /home/andale/CollegePortal
git worktree add -b <branch> /tmp/work origin/develop
cp backend/.env /tmp/work/backend/.env
# ОБЯЗАТЕЛЬНО следующей строкой: скопированный .env смотрит на рабочую базу стенда.
sed -i 's/^DB_DATABASE=college_portal$/DB_DATABASE=college_portal_test_<ваше-имя>/' /tmp/work/backend/.env
mkdir -p /tmp/work/backend/storage/framework/{cache,sessions,views} /tmp/work/backend/storage/logs /tmp/work/backend/bootstrap/cache
chmod -R 777 /tmp/work/backend/storage /tmp/work/backend/bootstrap/cache

V1="/tmp/work/backend:/var/www/html"
V2="/home/andale/CollegePortal/backend/vendor:/var/www/html/vendor:ro"
docker run --rm -e CP_WORKTREE="$(basename "$PWD")" -v "$V1" -v "$V2" -w /var/www/html collegeportal-backend php artisan test
```

**Так смонтирован только `backend/`, и проверки, которым нужен фронтенд, молча пропускаются.** `MenuMatchesPermissionsTest` ищет рядом `../frontend/src/layouts/AppLayout.vue`, не находит и честно пишет «пропущен». CI берёт дерево целиком, поэтому там он выполняется — и 23-24.08.2026 ствол простоял красным **90 прогонов подряд**, пока все четыре области читали «3 skipped» как «всё в порядке». **«Пропущено» — это вопрос, а не норма: прогон, часть которого не выполнялась, зелёным не является.** Перед вливанием правки, задевающей меню, роли или экраны, монтируйте дерево целиком:

```bash
V3="/home/andale/CollegePortal/backend/vendor:/tree/backend/vendor:ro"
docker run --rm -e CP_WORKTREE="$(basename "$PWD")" -v "/tmp/work:/tree" -v "$V3" -w /tree/backend collegeportal-backend php artisan test
```

**`$V2` сюда не годится, и до 03.09.2026 здесь стоял именно он.** Точка монтирования `vendor` идёт за рабочим каталогом: у прогона по `backend/` это `/var/www/html/vendor`, у прогона целым деревом — `/tree/backend/vendor`. С `$V2` рецепт не запускался **вовсе** — `artisan` падал на `require(/tree/backend/vendor/autoload.php)`, замерено. То есть рецепт, написанный ради `MenuMatchesPermissionsTest`, не выполнял ни одного теста, и попробовавший откатывался к прогону по `backend/`, где этот тест пропускается, — к тому самому состоянию, из-за которого ствол простоял красным 90 прогонов. **Проверять надо не только что рецепт написан, но и что он запускается.** Признак, что дерево смонтировано целиком: `MenuMatchesPermissionsTest` в выводе `PASS`, а не `skipped`; замер того же дня — 1292 теста, 0 пропущенных.

`CP_WORKTREE` здесь нужна ровно так же, как в прогоне по `backend/`: без неё сторож тестовой базы не сверит имя базы с вашим worktree.

Образ бэкенда называется `collegeportal-backend`. Зависимости `vendor` монтируются из основного checkout — в worktree их нет.

Прогон на PostgreSQL, который ближе к бою, чем SQLite по умолчанию:

```bash
docker exec college_dev_postgres psql -U college_user -d college_portal -c "CREATE DATABASE college_portal_test"
# в .env worktree выставить DB_CONNECTION=pgsql, DB_HOST=postgres, DB_DATABASE=college_portal_test
docker run --rm --network collegeportal_default -v "$V1" -v "$V2" -w /var/www/html collegeportal-backend \
  php artisan test -c phpunit.pgsql.xml
```

Сборка фронтенда:

```bash
docker run --rm -v "/tmp/work/frontend:/app" -w /app node:22-alpine npm run build
```

Монтировать `node_modules` только на чтение нельзя: Vite пишет временные файлы. Копируйте каталог либо ставьте зависимости заново.

И **сам признак «экран ответил» должен подходить экрану**: «Воспитательная работа» при здоровом экране не даёт ни строки, ни пустого состояния, ни баннера — сводка нарисована текстом, и узкий признак объявил исправный раздел неотвечающим. **Это не отменяет строку «глазами не смотрел» в передаче** — она теперь означает другое: не «не мог», а «не стал».

## Локальная рабочая копия всегда актуальна

**Владелец читает код и документацию в локальной копии, а не на серверах.** Поэтому она обязана быть на текущем стволе.

`C:\!Projects\CollegePortal` стоит на ветке `develop`, которая отслеживает `dev/develop` — remote `dev` подключён к DEV по SSH:

```
dev  ssh://andale@192.168.34.114/home/andale/CollegePortal
```

Через `origin` обновляться нельзя: он подключён по HTTPS и потребует интерактивной авторизации. Через `dev` работает по ключу, без вопросов.

Обновление локальной копии — одна команда:

```bash
git fetch dev && git merge --ff-only dev/develop
```

Настроено `pull.ff only`, поэтому случайный merge-коммит в локальной копии не появится.

**Правило сессии: закончив работу и отправив коммиты, обновите локальную копию этой командой.** Иначе владелец читает старый код, а найденные им «ошибки» окажутся уже исправленными.

Ветка `dev-line` — историческая, для работы не используется. Состояние её рабочего дерева на 08.08.2026 сохранено в `safety/dev-line-local-20260808`; проверено, что уникального кода в нём не было.

## Ветки и релизы

Ствол — `develop`. CI запускается на `develop`, `main` и ветках `feature/**`, `fix/**`, `sync/**`, `rescue/**`, `ci/**`; проверяет политику путей, тесты на SQLite и на PostgreSQL 17, сборку фронтенда и поиск секретов.

Push с рабочей станции невозможен: удалённый репозиторий подключён по HTTPS и потребует интерактивной авторизации. **Коммиты и push делаются с DEV**, где настроен доступ по SSH-ключу.

Релиз собирается только на DEV и только при чистом рабочем дереве:

```bash
bash scripts/release/build-release.sh
```

Сначала поднимите версию в `installer/VERSION`, затем соберите, затем ставьте тег — **тег на коммит сборки, а не заранее**. Обновление PROD:

```bash
# с рабочей станции, через служебную учётную запись
scp releases/college-portal-<версия>.tar.gz cp-agent@192.168.34.99:/home/cp-agent/
ssh -i .local/ssh/cp-agent cp-agent@192.168.34.99 \
  "sudo -n /opt/college-portal/installer/update.sh /home/cp-agent/college-portal-<версия>.tar.gz"
```

Скрипт сам делает резервную копию, включает режим обслуживания, мигрирует и проверяет здоровье. При неудачной проверке он **запрашивает подтверждение отката интерактивно** — в неинтерактивной сессии это не сработает, и скрипт просто завершится с ошибкой. Откат тогда делается отдельным вызовом `installer/restore.sh` с путём из строки `Backup before update:` в выводе. Если обновление запускает человек, лучше делать это в `tmux`: сессия переживёт обрыв связи и вопрос об откате дойдёт до терминала.

## Грабли, на которые уже наступали

- `frontend/public/version.json` генерируется при каждой сборке и не отслеживается в git. Не возвращайте его под контроль версий: сборка релиза требует чистого дерева и перестанет работать дважды подряд.
- `frontend/Dockerfile.release` сохраняет `version.json` из архива поверх сгенерированного. Без этого релиз представляется как `dev-unknown` в окружении `development`.
- `.env` на PROD принадлежит root. Команды, которые его читают, целиком заворачивайте в `sudo bash -c '...'`.
- Резервные копии PROD лежат в `/var/backups/college-portal`, а не в `/srv/backups`, как написано в README.
- **Право объявляется у маршрута** — `->middleware('permission:students.view')`. Таблицы префиксов в `EnsurePermission` больше нет (`ARCH-001`, шаг 3, 10.08.2026), выводить право из URL не нужно и негде. Несколько проверок на одном маршруте складываются через **И**, альтернативы внутри одной перечисляются через запятую и складываются через **ИЛИ**: `permission:digitalpasses.manage,view_own_data`. Маршрут закрытой части без объявленного права роняет `PermissionTableAndProxyTest` — либо допишите право, либо внесите маршрут в список открытых каждому вошедшему прямо в тесте.
- **Новое право обязано появиться миграцией, а не только в `RoleSeeder`.** Сидер выполняется при установке и больше никогда: `installer/update.sh` запускает миграции и ничего кроме. На этом уже потерялись `gate.points.manage` и `students.bulk_accounts` — объявлены в сидере, в базе установленной системы отсутствовали, и выдача прав их молча пропускала. Обратное тоже верно: право, заведённое только миграцией, сотрётся на новой установке, потому что `RoleSeeder` раздаёт права через `sync()`.
- **Роль тоже обязана приходить миграцией.** Раньше роли заводил только `RoleSeeder`, и роль, добавленная после установки, до обновлённой системы не доезжала: `study_records` пришлось поднимать на PROD руками 17.08.2026. Зелёный обратный тест при внесённом дефекте неотличим от зелёного обратного теста при исправном коде, поэтому достижимость подтверждайте отдельно — например, убедитесь сначала, что прямой вызов делает то, чего сторож ждёт. **И у этого правила есть край: бывает сторож, который обязан оставаться зелёным.** 30.08.2026 такой поставлен на совместимость — «файл без новой колонки грузится как раньше»; он не краснеет ни на одном внесённом дефекте, потому что охраняет то, что **не должно** сломаться. Разница не в том, краснеет ли сторож, а в том, сказано ли **в нём самом**, что именно он не даёт сломать. Без такой оговорки следующий вычеркнет его как бесполезный — и правку ради нового сломает старое. **И у зелёного на дефекте сторожа есть второй вид, который с первым легко спутать: тот, что просто не о том.** 31.08.2026 проверка «причина пропуска не течёт со строки на строку» осталась зелёной при выключенном `forgetSkipReason()` — не потому, что охраняла несломанное, а потому, что течь причине было **некуда**: все пятнадцать мест повод называют. Проверка утверждала то, чего не проверяла. **Различить два вида можно одним вопросом: какой именно дефект сторож обязан поймать — и внести именно его, а не тот, о котором думаешь.** Автор внёс второе.
- **Сторож должен читать то, что охраняет, а не помнить наизусть.** Список внешних ключей, переписанный в тест руками, однажды разойдётся со схемой и промолчит: у `groups` их оказалось девять (семь `CASCADE` и два `SET NULL`), а в устном списке было семь. `App\Support\Groups\GroupDependencies` закрыт тестом, который **читает ключи из самой схемы** и падает на появившемся новом. Тот же приём годится любому месту, где проверка перечисляет что-то, что может вырасти.
- **Прежде чем объявлять потерю, дочитайте то, что уже сохранилось.** Лог прогона держите целиком, `tail` делайте по файлу — но дороже сегодня обошлось другое: `... | tail -6` **оставил** последний кадр стека с именем файла и номером строки, а прочитана была только строка с числами. Вывод «имя упавшего теста потеряно» оказался неверным, и за него заплатили четырьмя лишними прогонами, отдельным worktree на чистом стволе и задержкой вливания у соседа. Данные лежали в том же файле всё это время.
- **В `docker run` подстановки, которые должны посчитаться на DEV, экранировать нельзя.** Заэкранированная подстановка выполняется **внутри контейнера**, где `id` равен нулю, и `chown` назначает файлы `root` вместо `andale` — то есть попытка починить права их доламывает, а разобрать потом можно только с `sudo`, которого у чатов нет. Пишите числа: `1000:1000` однозначны.

- **Перед `push` смотрите, что именно уедет: `git log origin/develop..develop`.** Областей четыре, репозиторий один, и локальный `develop` на DEV почти всегда несёт чужое влитое, но не отправленное. `push` увозит его молча: 24.08.2026 так опубликовали чужой коммит на несколько минут раньше, чем автор успел починить найденное им падение, — и ствол постоял красным по чужой вине. Ничего не пропало, но момент публикации выбрал не автор.
- **Между перебазированием и отправкой обязателен прогон.** Ветка, зелёная на своём основании, ничего не обещает на новом: ствол за день уезжает по нескольку раз, и сосед мог добавить таблицу, ключ или сторожа, которых ваша ветка не видела. Проверено дважды за один день — сторож `GroupDependencies` уронил ствол ровно на таком стыке.
- **Случайность в помощниках тестов даёт мигание, и порог у него — число вызовов.** Код вида `'SOLF'.random_int(100, 999)` при уникальном столбце сходит с рук, пока помощника зовут по разу за тест: три вызова — меньше процента, десять — около пяти, двадцать — почти двадцать. Новый тест, зовущий помощника двенадцать раз, дал совпадение примерно в 7 % прогонов, и выглядело это как «отмена занятия иногда не работает» — искали бы в рассылке, а не в генераторе кодов. **«Раньше не мигало» ничего не значит:** помощник тот же, а число вызовов новое. В помощниках пишите счётчик, а не случайное число.

- **Прогон на PostgreSQL берёт имя базы из `.env` вашего worktree, и по рецепту выше этот `.env` наведён на рабочую базу стенда.** `phpunit.pgsql.xml` задаёт `DB_CONNECTION`, но **не задаёт `DB_DATABASE`** — и не может: четыре области гоняют прогоны одновременно, общее имя они затирали бы друг у друга. А `RefreshDatabase` сносит схему и наполняет заново. 24.08.2026 на DEV нашлось **22 worktree**, чей `.env` смотрел на `college_portal` с 593 настоящими студентами: один `artisan test -c phpunit.pgsql.xml` в любом из них уничтожил бы контингент, группы, карты и пропуска целиком. Не сработало по случайности — каждый чат уводил прогоны в свою базу по привычке, а не потому что что-то мешало ошибиться. **Опасен не `.env` после прогона, а любой свежескопированный:** ни один из тех двадцати двух не «вернули как было», их просто ни разу не переводили. Поэтому строка `sed -i` в рецепте — не совет, а часть заведения worktree.
- **Прибираясь за собой, не возвращайте `.env` worktree «как было».** «Как было» — это указатель на рабочую базу. После прогонов он должен смотреть на **несуществующее** имя (`college_portal_NO_SUCH_DB_<worktree>`), а в мёртвом каталоге `.env` лучше удалить совсем: тогда `artisan` там просто не стартует. Инстинкт аккуратности здесь возвращает заряженное ружьё.

- **Прогон отказывается идти по базе, которая не ваша.** Сторож работает до `RefreshDatabase`: прогон падает, если имя базы не названо тестовым (в нём нет `test`) или, при переданной `CP_WORKTREE`, не называет ваш worktree. Общая `college_portal_test` разрешена всегда, `sqlite` и `:memory:` не трогаются. Поэтому в `docker run` передаётся `-e CP_WORKTREE="$(basename "$PWD")"` — без неё второе правило не включится, и останется только первое.
- **Если в пояснении стоит «никогда» или «всегда» — рядом должно стоять, на чём это замерено, иначе слово лишнее.** Врущий комментарий опаснее отсутствующего: он **останавливает проверку**. За 24.08.2026 на это наступили четыре раза, и ни разу утверждение не было прямо неверным — каждое было **сужено до случая, который смотрели**, и записано в тоне проверенного: «`find` по значению заголовок не найдёт» (находил, и печатная ведомость подписала пятерых живых людей чужим заголовком), ссылка на защиту, которой не существует, объяснение «администратор проходит мимо прав через `Gate::before`» (право выдавалось миграцией), «у отказов `ESS1` пуст» (верно для одного типа отказа из двух).
- **Числа стареют за полчаса, поэтому называйте час замера вместе с числом.** Четыре области чинят одно и то же одновременно: 24.08.2026 два чата разошлись в счёте заряженных `.env` — 22 против 13 — и оба были правы, просто мерили с разницей в час. Расхождение в методе и расхождение во времени выглядят одинаково, а стоят разного.

- **Не пишите в комментарии утверждения, которое нельзя проверить на месте.** Правило «рядом с „никогда“ должно стоять, на чём замерено» — про чтение; это про письмо, и стоит оно дороже: врущий комментарий наказывает того, кто **как раз читал внимательно**. «Администратор проходит мимо прав через `Gate::before`» проверить негде — надо знать всё приложение. «Право выдаёт миграция `2026_08_23_000001`» проверяется одной командой. Разница не в вежливости формулировки, а в том, оставил ли автор способ себя опровергнуть.
- **Часовой пояс: `app.timezone` менять нельзя.** Выглядит правкой в одну строку, а Laravel начнёт **записывать** местное время рядом с двумя годами UTC, и различить их потом будет нечем: **расхождение на части строк хуже ровного расхождения на всех**. Лечится тремя частями, и порядок обратен интуиции: сначала границы суток (там строки **пропадают** — отбор «за 22-е» даёт ноль на карте, выданной 22-го), потом один общий форматировщик на фронтенде (37 вызовов `toLocale*` в 27 файлах, `timeZone` не задан ни в одном), потом перевод времени в выгрузках. Разбор — [docs/TIME_ON_PRINTED_DOCUMENTS.md](docs/TIME_ON_PRINTED_DOCUMENTS.md).

- **Часовой пояс чинится только там, где день человека сравнивается с колонкой `timestamp`.** У колонки `date` пояса нет, и перевод в пояс её **ломает**: журнал и расписание сравнивают дату с датой, там трогать нечего, хотя `startOfDay` в них есть. Оценка «24 вызова, чинить все» была вдвое завышена, и сузил её **замер схемы, а не чтение кода**. Самое неочевидное место оказалось не в отборе, а в пороге: «восемь утра» у ночных отсутствий считалось по часам сервера, и окно ночи было сдвинуто на три часа — никакой отбор по датам этого не вскрыл бы.
- **«Нельзя посмотреть» — утверждение об инструменте, и его надо мерить, а не выводить.** 24.08.2026 в передаче появилась строка «отчёт заселённости и лист на дверь требуют более длинного сценария, чем умеет `look.js`» — написанная по чтению кода инструмента, без единой попытки. На деле оба листа снялись **существующими ключами с первого раза**: поля периода заполнены по умолчанию, кнопка обычная. Два документа простояли неувиденными четыре дня, и прочитать эту строку следующий мог только как ограничение инструмента. **«Не смотрел» и «нельзя посмотреть» — разные утверждения: первое про себя, второе про мир, и второе требует замера.**
- **Счётчик проверяйте не только на том, что он считает, но и на том, что он способен увидеть.** Подпись «заголовок `PageHeader`: нет» врала на **каждом** разделе, потому что искала класс, которого в компоненте не существует: инструмент уверенно отвечал «нет» на вопрос, который не умел задать. Рядом «сообщений об ошибке: 0» стояло при красной полосе на экране. Внешний признак, по которому это ловится без чтения селектора: **счётчик, ни разу не ответивший «да», подозрителен сам по себе.**

- **Печатный лист владельцу и файл загрузки собирайте из одного источника.** 28.08.2026 список дисциплин уточнялся трижды, лист пересобирался, **а файл загрузки нет** — и в портал уехал бы набор, не совпадающий с листом, который владелец держит в руках: на единицу, с двумя заголовками разделов внутри. Заметить это в базе потом почти нечем. Связь между документом и данными, держащаяся на том, что автор помнит про оба, — это не связь; сборка обязана падать, если числа разошлись.
- **Со станции на DEV отправляйте файл, а не поля формы.** CSV в UTF-8 с BOM через `scp` доходит целым, а кириллица в значениях полей `curl` из Git Bash на Windows долетает как `??????????` — сопоставление колонок не находится, и все строки отказывают с «заполните поле». Выглядит как испорченный файл, а испорчена команда. Загрузку запускайте с DEV.

- **Вкладка со своим источником данных обязана грузить их при открытии, а не по кнопке.** На экране бланков три вкладки из четырёх наполнял общий вызов при входе, а книгу регистрации — только «Обновить»: открывший вкладку видел пустую таблицу, подпись «Выданных дипломов пока нет» и **погасшую кнопку печати**, которая отключается по числу строк. Подпись утверждала о колледже то, что верно было только про экран. Замер 28.08.2026: ноль строк при пяти выданных дипломах, после «Обновить» — пять и лист на пять. Фронтенд-тестов в репозитории нет вовсе, такое ловится взглядом и ничем иным.
- **Одно число, записанное в двух местах, разойдётся молча — и разойдётся там, где его печатают.** Серия и номер бланка хранились и в дипломе, и в учёте бланков, а связь шла в одну сторону: закрепление писало в диплом, обратно не писал никто. Отсюда три способа расхождения, каждый в один щелчок: снятие закрепления оставляло номер в дипломе, диплом, заведённый после закрепления, не получал номера вовсе, а набранный руками номер уезжал в книгу как есть. Заводя второе место для того же числа, сразу называйте, какое из них источник, — и ставьте правило **на модель**, а не в контроллер: путей записи у диплома оказалось три.

- **`lower()` в SQLite не опускает кириллицу, и движки расходятся в обе стороны.** Замер 28.08.2026 прямо в контейнере: SQLite `lower('Иванов')` возвращает `Иванов`, а `mb_strtolower('Иванов')` в PHP — `иванов`; сравнение в запросе ложно всегда, человек не находится, команда молча не доходит до итоговой строки. На PostgreSQL то же выражение работает. Выше записана эта же грабля **только одной стороной** — исключение на уникальность зелено на SQLite и красно на PostgreSQL. **Зеркало опаснее оригинала:** первый случай увидит любой, кто гоняет «поближе к бою», второго он не увидит никогда, и ловит его только CI, потому что CI гоняет оба. Регистр опускайте в приложении с обеих сторон сравнения — тогда движок в нём не участвует вовсе и расхождение не может вернуться ни на одном. **Гонять оба движка ничего не стоит:** SQLite идёт в памяти, PostgreSQL в вашей базе, они не сталкиваются.
- **Проверка, стоящая в одном вызове с действием, проверкой не является.** `git log origin/develop..develop`, выведенный тем же скриптом, что делает `push`, печатается и тут же уезжает: взгляд есть, решения нет. Обратная форма того же — `git merge --ff-only … || git merge --no-edit …`: отказ первой половины и есть то условие, ради которого написана вторая, и она выполняется молча, в общем выводе. **В команде, способной сделать необратимое, `||` — не страховка, а второй сценарий.** Оба случая 28.08.2026, оба привели к действию, которого никто не решал: опубликован чужой невлитый коммит и сведена ветка, сведение которой было отложено.
- **Релиз собирается из рабочего дерева DEV, а CI проверяет `origin`** — совпадают они только по привычке. 28.08.2026 они разошлись на шесть коммитов, и сетка звонков уехала бы на боевой, ни разу не увиденная CI: проверил её человек руками. Перед сборкой сверяйте `git log origin/develop..develop` и либо отправляйте, либо называйте вслух, что едет непроверенным. И помните, что **отказ `git merge --ff-only origin/develop` — это не «уже актуально», а «на DEV лежит неотправленное, посмотрите что»**: правило выше написано для случая, когда DEV только отстаёт, а при расхождении оно молча отказывает. **И обратная сторона того же: замеряя на `origin`, вы меряете состояние, которого нет ни на стенде, ни на боевом.** 30.08.2026 область подняла пробу из `origin/develop`, нашла «дефект» в загрузчике аудиторий и чуть не записала его находкой — а починка (`a1028ff01`) полтора суток лежала в неотправленной стопке. Прежде чем объявлять дефект, посмотрите `git log origin/develop..develop`: если там что-то есть, вы меряете не то, что работает у людей.
- **Экран, сам сообщающий верное число и показывающий другое, — это не косметика.** 28.08.2026 «Студенты» показывали 20 строк при собственной подписи «Найдено записей: 596»; так же врали ещё восемь списков, включая людей (30 из 841) и цифровые пропуска (50 из 843). Причина одна: при разборе ответа берут `data` и выбрасывают `meta` — страница и полный список в коде **неразличимы**, и хранилище не может узнать, что ему отдали не всё. Лечится одним местом, а не перечислением `per_page` по вызовам: число устареет так же, как устарело умолчание. И проверять надо **запросом к порталу** — `data.length` против `meta.total`, — а не чтением кода: `semesterGrades.js` честно слал `per_page: 500` и получал 20, потому что контроллер параметр не читал вовсе. Написанное есть, действия нет.
- **Один прогон на одну базу, и никаких правок под идущим прогоном.** `RefreshDatabase` сносит схему и наполняет заново; два прогона по одной базе снесли её друг у друга и дали 31 и 5 «падений», не имеющих отношения к коду. Признак различимый и годится шире: **числа, не сходящиеся между собой**, — это отказ метода, а не находка в коде. В тот же вечер по этому признаку был снят негодный поиск номеров карт в двоичном файле базы.

- **Настройка, объявленная только в каталоге умолчаний, до браузера не доезжает.** `SettingService::definitions()` наполняет базу лишь тогда, когда значение спросят **на сервере**, а печатный документ собирает браузер и читает публичные настройки из базы напрямую: строки нет — поле молча пустое. 28.08.2026 так вышел бланк справки без реквизитов колледжа и с фамилией директора над пустым местом; из кода это не видно вовсе, ловится только взглядом на готовый лист. Это тот же класс, что права и роли: сидер выполняется при установке и больше никогда. **Новая настройка обязана приходить миграцией.**
- **Печатать саму страницу — проигрышная позиция, и проигрыш молчаливый.** Блок `@media print` обязан быть не-`scoped` (иначе `body *` спрячет только свои узлы), а раз он не-`scoped`, соседний `<style scoped>` несёт `[data-v-...]`, весит больше и перебивает его при любом порядке в файле. Замерено 28.08.2026 на карточках с учётными данными: сетка давала шесть колонок вместо трёх, вычисленный цвет рамки — `rgb(153, 153, 153)` вместо чёрного, и серая линия реза уезжала на бумагу. Лечится не весом, а тем, что печатать перестают страницу: `printHtmlDocument` и `printPage` из `frontend/src/utils/print.js` собирают **отдельный документ** со своими стилями, куда каскад приложения не приходит вовсе. Так печатают ведомость карт, книгу регистрации дипломов и справки студентам. **Проверяется только вычисленным стилем в браузере** при `emulateMedia('print')` — ни сборка, ни прогон этого не видят.

- **Пустое состояние обязано отличать «данных нет» от «спросить не удалось».** Пока не отличает, любая поломка ниже превращается в **утверждение о колледже**: 28-29.08.2026 так вышло трижды подряд — «Выданных дипломов пока нет» при пяти выданных, «1 - 20 из 20» при 596 студентах и «Справок пока не выдавали» при таблице, которой в базе не существовало вовсе. Последнее владелец прочитал как факт и попросил завести журнал, который уже был. **И число рядом с подписью врёт отдельно:** «Выдано справок: 0» осталось на экране даже после того, как подпись стала честной — считать было нечего, а ноль называли. Число называйте только когда его посчитали. **Частая причина, по которой не отличает: `Promise.allSettled`.** Отказ запроса он не роняет, а превращает в отклонённое обещание, из которого экран берёт пустой список — и пустой список после неудачи неотличим от пустого расписания. 30.08.2026 отсюда росло зелёное «Свободно» на первом экране преподавателя. Разбирайте `status` каждого обещания, а не только `value`.
- **Правка, меняющая то, что фронтенд шлёт всем ручкам, ломается там, где ручка проверяет вход сама.** 29.08.2026 общий помощник стал просить `per_page=500`, а пять контроллеров держали собственный потолок 200-300 и отвечали **422**: экран рисовал пустое состояние, счётчики показывали нули, CI был зелёный, ошибок в консоли не было. Нашёл владелец глазами за минуту. Ловится только запросом к каждой ручке — код и прогон по отдельности выглядят правильными. **Потолок в контроллере, объявленный отдельно от общего, — это будущее расхождение:** сводите к одному месту, а сторож пусть посылает предельный запрос и требует ответа, а не ищет `max:` по исходникам.
- **Сторож, кричащий на невиновных, — это выключенный сторож.** Его отключат или перестанут читать, и он не спасёт там, где был нужен. 29.08.2026 проверка потолков сначала обвинила четыре контроллера, у которых сотней ограничена длина названия, потом покраснела на комментарии в самом помощнике, где неправильный вызов приведён как пример. Чинится **сужением якоря**, а не поднятием порога терпимости: порог заглушил бы и настоящие случаи.

- **Печать страницы при открытом модальном окне даёт ровно один лист.** Quasar на время окна вешает на `body` класс `q-body--prevent-scroll` и делает его `fixed`: поток документа исчезает, и всё ниже первого экрана не печатается **вовсе**. 29.08.2026 так терялся лист учётных данных — 27 карточек занимали 1410 px при листе 1123 px; владелец увидел на бумаге 15 из 27, автор правки при более широком окне 21 из 27, в файле одна страница. Заметить нечем: разметка полная, строки на месте, предпросмотр показывает первую страницу и выглядит правильно, — а пароль показан один раз и в базе лежит только его отпечаток, то есть двенадцать человек остались бы без доступа. **Решающий опыт — один переключатель:** снять с `body` этот класс, не трогая больше ничего, — поток документа 1000 → 1052 px, страниц 1 → 2.
  **Что при этом не виновато, замерено отдельно и вопреки первой записи в этом файле:** `position: absolute` печать **не** режет, нынешний Chromium такой блок переносит сам (60 строк — 2 страницы); и печать страницы портала сама по себе многостраничная (список студентов на 600 строк — 2 листа). **Режут** `position: fixed` и «фиксированная высота + `overflow: hidden`» — те же 60 строк дают одну страницу вместо двух. Лечение прежнее: собирать **отдельный документ** через `printHtmlDocument`, куда ни каскад приложения, ни замок `body` не приходят. Проверять — числом страниц и числом строк на них, на заведомо длинном наборе.
- **Список людей не должен открываться чужой карточкой.** Раздел, который в `onMounted` выбирает первый элемент, показывает любому вошедшему чужую фамилию, чужой QR-код и чужой токен, и ставит чужой идентификатор в адресную строку. 28-29.08.2026 так вели себя выпускники, цифровые пропуска и учётные записи. **Разделяющий признак — стоит ли за строкой человек:** у ролей, настроек, учебных планов и пакетов ФИС автовыбор первого это удобство, а не утечка, и трогать его не надо. Сторож обходит каталог страниц сам, а осознанные исключения перечислены **с причиной у каждого**; и он же падает, если файл из списка исключений исчез или переименован — иначе строка молча прикрывала бы уже другое.

- **Застывшая высота ищется поведением, а не грепом по стилям.** `max-height: 320px` у списка подсказок безвреден, а `calc(100vh - …)`, посчитанный один раз, — нет, и отличить их можно только замером. Признак, найденный 29.08.2026 после четырёх таких дефектов подряд: **узел со своей полосой прокрутки, высота которого одинакова при разных размерах окна**. Растущий — норма, застывший — подозреваемый. Обход 26 экранов при 800 и 1400 px дал ровно **одного** застывшего, после правки — ноль. Сценарий лежит рядом с `look.js`: `/home/andale/.cp-screens/fixed-heights.mjs`; гоняйте его после правок вёрстки, он задаёт вопрос, на который ни греп по стилям, ни снимок не отвечают.
- **Память в прогоне больше не подозреваемый по умолчанию: замерено 200 МБ пика при лимите 1024** (29.08.2026, полный набор ~1174 теста), и пик теперь печатается в конце **каждого** прогона, зелёного тоже. Правило выше про потолок памяти остаётся верным как история, но проверка его теперь стоит одной строки вывода, а не отдельного прогона: **сначала посмотрите напечатанный пик, а уже потом стройте догадки**. И помните различающий признак: упор в память выглядит как «Allowed memory size exhausted» плюс десяток несвязанных падений, а обычные провалы утверждений — это порядок или состояние, а не память.

- **Мёртвые правила печати опаснее живых: они придают обрезанному листу вид документа.** 29.08.2026 в `StudentsPage.vue` остался блок `@media print` от старого способа — `body * { visibility: hidden }` и лист поверх, — хотя звавшего его кода давно нет. Рабочая кнопка печати была уже починена и собирала отдельный документ, а **Ctrl+P** при открытом окне по-прежнему давал **одну страницу с 21 карточкой из 27**: приложение скрыто, лист выглядит целым, обмануться нечем. То есть беда, стоившая двенадцати человек, пережила починку и жила через другую дверь. Такие правила **удаляйте, а не исправляйте**: единственное, что они ещё делали, — маскировали потерю. Закреплено `PagesDoNotPrintThemselvesTest`, который обходит каталог страниц сам и падает на блоке стилей, прячущем приложение ради печати себя, и на `window.print()` в странице; комментарии он снимает до поиска, а `@media print` **внутри собираемого документа** законен и его не трогает.

- **Сторож, ищущий форму записи, слеп к другой форме — за ночь 28-29.08.2026 это случилось трижды.** `ListsHonourPageSizeTest` ищет `paginate(N)` и не увидел `paginate((int) $request->integer('per_page', 50))` — ручку **без потолка вовсе**; он же ищет размер страницы в самом вызове и не увидел его в переменной, а жалоба во время работы увидела; и обход `listAll` по списку экранов, которые мы помним, пропустил `rfid-cards`, пока владелец не наткнулся на красную полосу. **Отсюда два следствия.** Первое: держите проверку кода и проверку поведения **обе** — они ловят разное, а не одно дважды. Второе, и оно важнее: **сторож закрывает повторение, а не нынешнее состояние**; разбор того, что уже написано, делается один раз и руками, по всем вызовам области, а не по тому, на что укажет сторож.

- **`--no-merges` — это не «содержательные», а «не-слияния», и на этом легко недосчитаться.** Там, где расхождение разрешают **решением**, а не автоматически, содержание оказывается **внутри** merge-коммита и через `--no-merges` не видно вовсе. Замер 29.08.2026: `git rev-list --count --no-merges origin/develop..develop` дал 9, а верное число — 12; в одном из трёх пропущенных слияний (`652419f6a`) внутри самого слияния **58 изменённых файлов**, включая удаление своей половины сторожа и переписывание его под чужой словарь — результат не совпадает ни с одним из родителей. Считайте `git log --oneline origin/develop..develop | grep -v "Merge remote-tracking"`: он выбрасывает синхронизацию со стволом и **оставляет решения**. И проверяйте спорное слияние `git show --cc --stat <хеш>` — если там есть файлы, содержание в нём и живёт.

- **«Сделай как рядом» относится к поведению, а не к проводке.** 30.08.2026 три места портала искали аудиторию по-разному; свели к **одному поведению** — пара «номер + корпус», спор отказывает с названной причиной, файл без корпуса грузится как раньше. А механизм отказа у них остался разным и должен был остаться: где импорт ловит исключение — исключение, где отчитывается валидатор — метка и правило. **Втащить чужую проводку в обработчик, который так не работает, — это и есть третий способ, а не единообразие.** И сообщение у каждого случая своё: «Аудитория не найдена» там, где она найдена и не одна, отправило бы человека искать опечатку, которой нет; верное — «есть в нескольких корпусах, укажите колонку „Корпус“».

- **Тест, зависящий от часа суток, краснеет окном — и «не воспроизвелось» тогда не значит ничего.** 29-30.08.2026 `AccessReportVolumeTest` мигал: одно падение, потом четыре зелёных прогона подряд, память ни при чём (пик 200 МБ из 1024). Разгадка: он падает **только с 21:00 до 24:00 UTC**, потому что сутки колледжа (UTC+3) начинаются на три часа раньше календарных, а посев в тесте брал `Carbon::today()` — календарный день. Двадцать один час в сутки они совпадают. **Прежде чем объявлять мигание случайностью, посмотрите на час прогона:** если падения кучкуются в окно, это не случайность, а зависимость. И **приспособление обязано брать сутки у того же источника, что код под проверкой** (`CollegeTime::todayDate()`), иначе в тот день, когда календарей станет два, тест начнёт врать раньше кода.
- **Замер стареет не только от времени, но и от чужих правок.** Комментарий у того же посева обещал «время в пределах сегодняшнего дня, чтобы счётчик „за сегодня“ считал их все» — и не врал, когда его писали. Неправдой его сделала правка **в другом файле**: сводку перевели на сутки колледжа. Правило «рядом с „всегда“ пиши, на чём замерено» этим дополняется: замер верен для того состояния кода, в котором сделан, и сосед может обесценить его, не тронув ваш файл.

- **Экран, показывающий «своё», строит фильтр из показанного, а не из общего справочника — и права ему для этого не нужны.** 30.08.2026 расписание преподавателя давало четыре отказа 403 на `groups`, `teachers`, `subjects`, `classrooms`, и в поле «Группа» у него было **ноль вариантов против 39 у администратора**. Соблазн — выдать роли недостающие права; замер показал, что это неверно: `ScheduleLessonController::applyScope` и так сужает выборку до собственных занятий, а выдача `teachers.view` открыла бы преподавателю перечисление 173 человек ради экрана, где видно четыре его пары. Правильно — брать значения **из самих занятий**: они приходят с вложенными группой, преподавателем, дисциплиной и аудиторией, и такой фильтр честнее общего, в нём нет чужих групп. **Прежде чем раздавать право «чтобы заработало», спросите, не просит ли экран лишнего.**
  **И сторож здесь ставится на договор, а не на права:** «преподавателю приходит только его занятие, и в каждом есть вложенные связи» плюс «четыре справочника ему по-прежнему закрыты». Иначе однажды уберут `->with([...])` ради экономии запроса — и фильтры опустеют молча, не там, где правили.

- **Прежде чем трогать чужую проверку, запишите словами, что она утверждает — зелёный тест своего прежнего смысла не хранит.** 30.08.2026 правка времени сделала бы `AccessReportFiltersTest` зелёным и **неверным**: выгрузка отчёта проходной отбирает по суткам колледжа, а печатает время в UTC (`AccessReportController:102`, `format('H:i')` без перевода) — то есть внутри одной ручки два календаря, и до правки **оба конца ошибались одинаково**, отчего проверка выглядела верной. Подгони ожидание под новую фикстуру — и она станет утверждать, что проход в четверть десятого печатается на листе как `06:15`. Поймано тем, что автор проверки записал её смысл **заранее и словами**: «во сколько прошёл, во столько и напечатано», а не «в выгрузке стоит такая-то строка». Смотреть «после правки» тут поздно: через неделю никто не вспомнит, что тест утверждал.
- **Сдвигая время, правьте фикстуры, а не ожидания — и помните, что замороженные часы тоже фикстура.** Признак правильной починки: **ни одно ожидаемое число со смыслом не изменилось**. 30.08.2026 из пятнадцати падений (у всех разница ровно 180 минут) изменились ровно два ожидания, и оба — **метки времени**, не смыслы: `first_entry '09:15' → '06:15'`, та же минута в UTC. `late_minutes: 15` и `17` остались нетронутыми. Чинить дешевле **помощника**, а не вызовы: одна строка в `entry()` сняла три падения. И `Carbon::setTestNow('08:00')` значит «восемь утра по колледжу», а не по UTC, — заморозка часов такая же часть посева, как само событие.

- **Проверка, убеждающаяся в форме ответа, читается как проверка ответа — и рядом с ней легко решить, что место покрыто.** 30.08.2026 тест выгрузки ведомости карт утверждал, что ответ начинается с `PK`, то есть что это zip; про содержимое — ничего, и подмена часа прошла бы мимо него целиком. Починка: сторож **распаковывает** книгу (`xl/sharedStrings.xml`) и ищет там «10.09.2026 09:15» для карты, выданной в четверть десятого по колледжу. **Это третий за сутки случай, когда проверка охраняет не то, что кажется:** счётчик, отвечавший «нет» на вопрос, который не умел задать (искал класс, которого в компоненте нет); «жалоб в консоли нет» при выключенном выводе; «это zip» вместо «в нём верное время». Общий признак точнее звучит так: **проверка стоит на пути к предмету, но до предмета не доходит** — «это zip» лежит на дороге к «в нём верное время» и потому читается как она. Тем и опасна: не соседнее утверждение, а **незаконченное**, и потому оно не краснеет никогда.

- **Пересказ чужого прогона наследует не ошибку, а состояние — а состояние стареет за минуты.** 30.08.2026 координатор передал «ствол, оба движка 1201/1, падает такая-то проверка»; числа были верны для **ветки автора до вливания**, а в стволе того падения не было никогда — там правка пришла уже сведённой. Сосед, собравшийся чинить эту красноту, **сперва прогнал ту проверку на чистом checkout** (полминуты) и нашёл её зелёной; поверь он на слово — влил бы красный ствол и объяснил его чужим коммитом, которого нет. **Прежде чем чинить чужую красноту, воспроизведите её у себя на стволе** — и не переносите чужие числа на другое место без замера, даже когда сами числа верны.

- **Прогон вне worktree — нарушение правила, но стенд при этом закрыт двумя защитами, а не одной.** 30.08.2026 полный прогон запустили прямо в основном checkout на DEV, где `.env` смотрит на рабочую базу стенда. Первый вывод автора — «уцелели по случайности, спасло только умолчание `phpunit.xml`» — **неверен, и проверен прямым вызовом сторожа**: `[pgsql] college_portal` → отказ «база не объявлена тестовой»; `[pgsql] college_portal_test` и `[sqlite] :memory:` → пропущены. Причина не в чьей-то небрежности: работа, отправленная явным refspec `git push origin HEAD:develop` из своего worktree, **в `develop` самого DEV не появляется вовсе** — а именно так отправлять и правильно, иначе увезёшь чужое. Отсюда: признак «нет в `develop`» и признак «нет в `origin`» — **разные вещи, и первый пугает зря**; сегодня по нему чуть не пошли спасать уже опубликованное. Мерьте обе стороны рядом: `git rev-list --count develop..origin/develop` и `origin/develop..develop`.
- **`git cherry` сверяет отпечаток патча, а не содержимое, — и «+» не значит «этого нет».** Ветка `rescue/student-marks-source-local` держала «+» семнадцать суток, а всё её содержимое **в стволе есть**: три ресурса и сторож совпадают дословно, а всё, что ветка удаляла (`JournalEntryService`, `AttendanceResource`, два теста, четыре Request), из ствола уже удалено. Работа приехала другим путём с другого основания, и отпечаток патча разошёлся. Поэтому «нет в `origin` ни под каким хэшем» — утверждение **о хэшах**, а не о содержимом: перед публикацией стопки сверяйте пофайлово, иначе повезёте дубликат. И помните, что само число живёт часами: 24 вчера, 27 и 28 сегодня.

- **«Правка есть в стволе» не значит «правка доедет до боевого»: стенд и боевой собираются разными файлами.** Замер 04.09.2026: починка числа рабочих процессов PHP лежала в `backend/docker/portal-entrypoint.sh`, была в стволе, была в origin, прошла CI — и не доезжала никуда. Образ стенда её подключает (`backend/Dockerfile`, строки 30-34: `COPY` плюс `ENTRYPOINT`), а `backend/Dockerfile.release` не содержит ни того, ни другого: там `USER www-data` и `CMD ["php-fpm"]`, php-fpm стартует напрямую, настройка пула не создаётся никогда, и остаётся умолчание образа — **пять процессов при шестнадцати ядрах**. Релиз ради этой починки был собран, и увёз бы на боевой всё, кроме неё. **И у этого есть вторая половина, из-за которой одного `ENTRYPOINT` было бы мало:** релизный образ работает от `www-data`, а `/usr/local/etc/php-fpm.d` принадлежит root, и скрипт при отказе записи молча идёт дальше — то есть дописанный `ENTRYPOINT` дал бы те же пять и ни одной строки в логе. Настройку, которая обязана быть в бою, пишите **на сборке, root'ом, до `USER www-data`**. Проверяется только числом, снятым **изнутри собранного релизного образа**, до и после, — чтение исходника здесь успокаивает зря.

- **Сторож тестовой базы требует имя worktree целиком, с дефисами, — и его отказ выглядит как расхождение движков.** Замер 04.09.2026: прогон в worktree `curator-trunk-check` на базе `college_portal_test_curator` дал **28 падений на PostgreSQL при нуле на SQLite** — готовая «находка» в приёмной комиссии, которой не было. `TestDatabaseGuard` требует, чтобы имя базы **содержало** имя worktree; `curator` не содержит `curator-trunk-check`. Правильное имя — `college_portal_test_<worktree>` со всеми дефисами, и в `psql` его надо брать в кавычки: `CREATE DATABASE "college_portal_test_my-branch"`. **Различающий признак, дешевле чтения лога: среди падений есть чисто логические проверки** — контрольная сумма СНИЛС базы не касается вовсе, и если она «упала на PostgreSQL», упал не код. Настоящее расхождение движков так не выглядит.

- **Спрашивайте по файлам, а не по авторам: «нет моих файлов» прочнее, чем «нет моих коммитов».** Собирая стопку к публикации, не перебирайте авторов — коммит можно не узнать, особенно чужой merge-коммит, внутри которого лежит содержание (`--no-merges` его не покажет). Раздайте каждому его кусок по именам файлов: `git log origin/develop..develop --name-only --pretty=format: | sort -u`. Приём принесла область «Студенты и документы» 04.09.2026, и он же поймал обратное: три файла совпали по подстроке области и все три оказались чужими.

# Backend: локальные правила

- Соблюдать Laravel conventions и текущую модульную структуру проекта.
- Считать PostgreSQL источником истины; SQLite использовать только там, где тест явно не зависит от PostgreSQL semantics.
- Изменять схему только обратимыми миграциями. Не удалять данные без отдельного задания и backup plan.
- Валидацию выносить в `FormRequest`, ответы — в API Resources, бизнес-логику — в Service Layer.
- Проверять RBAC на backend по permission и scope объекта; скрытие кнопки во frontend не является защитой.
- Логировать изменяющие операции через Audit без ПДн, секретов и содержимого файлов.
- Файлы с ПДн хранить в private storage и выдавать только через авторизованный controller.
- Для сложных изменений использовать транзакции, idempotency и явную обработку повторных запросов.
- Validation messages и пользовательские ошибки писать по-русски.
- Добавлять Feature tests: успешный сценарий, validation, permission `403`, scope и regression cases.
- Не выводить в логи паспортные данные, СНИЛС, токены, credentials и содержимое private documents.

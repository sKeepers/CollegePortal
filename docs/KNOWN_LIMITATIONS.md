# Известные ограничения MVP CollegePortal

Документ фиксирует ограничения состояния после MILESTONE-002 и перед первым UAT.

## Общие ограничения

- Это DEV/MVP, а не промышленный релиз.
- Интерфейс и процессы требуют пользовательской проверки на реальных сценариях колледжа.
- Реальные персональные данные нельзя загружать в тестовую среду без отдельного решения по безопасности и правовым требованиям.
- Матрица прав доступа требует отдельной детализации по ролям колледжа.
- Часть Dashboard-виджетов и мобильных блоков может использовать тестовые или неполные данные.

## ФРДО

- Нет реальной интеграции с ФРДО.
- Нет отправки данных во внешнюю систему.
- Реализована только подготовка, проверка полноты, статусы и экспорт CSV/JSON.
- Требуется сверка с актуальными официальными форматами и регламентами.

## ФИС ГИА / ФИС Приема

- Нет реальной интеграции с ФИС.
- Нет отправки данных во внешнюю систему.
- Реализована только подготовка пакетов, проверка полноты, статусы и экспорт CSV/JSON.
- Требуется сверка с актуальными официальными форматами ФИС ГИА и ФИС Приема.

## QR и проходная

- QR работает в MVP-режиме.
- QR содержит token, а не персональные данные.
- Физический USB QR-сканер нужно проверить отдельно на рабочем месте проходной.
- Нет NFC/RFID.
- Нет Face ID.
- Нет распознавания лиц.
- Нет интеграции с турникетами или СКУД.
- Правила допуска пока базовые: активный token разрешает проход, отозванный/неизвестный token дает отказ.

## Mobile Student

- Мобильный кабинет реализован как MVP.
- Нет push-уведомлений.
- Нет офлайн-режима.
- Нет отдельного мобильного приложения в магазинах приложений.
- Часть данных зависит от связки текущего пользователя со студентом.
- Требуется проверка на реальных телефонах студентов.

## Учебный процесс

- Расписание, журнал, учебные планы, нагрузка, экзамены и выпускники реализованы как рабочий MVP.
- Требуется наполнение реальными учебными данными.
- Требуется проверка терминологии с учебной частью.
- Печатные формы дипломов и приложений к диплому пока не являются финальными официальными шаблонами.

## Инфраструктура

- PROD не менялся при подготовке UAT.
- DEV и PROD разделены, но реальный деплой должен выполняться только по отдельной процедуре.
- Frontend build проходит, но есть предупреждение о крупном JS chunk. Нужно запланировать code splitting.

## Уведомления и внешние сервисы

- Нет push-уведомлений.
- Нет Telegram/email-уведомлений в промышленном режиме.
- Нет Moodle-интеграции.
- Нет LDAP/Active Directory-интеграции.
- Нет реальной интеграции с 1С.

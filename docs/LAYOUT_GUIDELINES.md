# Layout Guidelines CollegePortal

## Общий layout рабочих страниц

Рабочие страницы CollegePortal строятся как плотный desktop-интерфейс для сотрудников колледжа. Основной сценарий: пользователь работает с таблицей слева и карточкой выбранной записи справа.

Базовая структура:

- верхняя панель приложения;
- левое навигационное меню;
- рабочая область страницы;
- фильтры и действия над таблицей;
- таблица в левой колонке;
- карточка выбранной записи в правой колонке.

## Ширина левого меню

Основной sidebar приложения:

- desktop: `286 px`;
- на узких экранах меню может сворачиваться штатным поведением Quasar drawer;
- рабочие страницы не должны рассчитывать свою ширину вручную с учетом sidebar, это делает `q-layout`.

## Правая карточка

Правая карточка используется для выбранной записи: студент, группа, преподаватель, дисциплина и другие будущие сущности.

Рекомендуемая ширина:

- минимум: `380 px`;
- обычное значение: `400 px`;
- максимум: `420 px`.

Карточка должна находиться в отдельной grid/flex-колонке, а не позиционироваться поверх таблицы.

## Таблица + карточка

Для страниц вида “таблица + карточка” использовать CSS Grid:

```css
grid-template-columns: minmax(0, 1fr) clamp(380px, 28vw, 420px);
```

Правила:

- левая колонка занимает все доступное пространство;
- правая колонка имеет ограниченную ширину;
- у левой колонки обязательно `min-width: 0`;
- у контейнера таблицы обязательно `overflow: hidden`;
- горизонтальная прокрутка должна быть внутри таблицы, а не на всей странице;
- последние колонки таблицы не должны уходить под карточку.
- если после sidebar рабочая область становится слишком узкой, карточка переносится под таблицу.

## Изменяемые двухпанельные рабочие области

Страницы с рабочей областью “список + карточка”, где оператору нужно регулярно менять фокус между таблицей и деталями, могут использовать draggable splitter. Текущее эталонное применение: `/people`.

Правила splitter:

- левая панель должна оставаться `minmax(0, 1fr)`;
- правая панель должна иметь минимальную ширину, достаточную для карточки Person;
- splitter не должен создавать горизонтальную прокрутку всей страницы;
- на узких экранах splitter скрывается, а панели переходят в одну колонку;
- выбранная ширина хранится только локально в браузере;
- должна быть доступна команда сброса ширины.

Ключ localStorage для страницы People:

```text
collegePortal.people.splitter.v1
```

Сброс размера возвращает правую панель к стандартной ширине `400 px`.

## Сворачиваемые разделы навигации

Группы sidebar должны поддерживать локальное сворачивание без обращения к backend. Это не заменяет штатное сворачивание всего sidebar в mini-режим.

Правила:

- заголовок группы является кнопкой;
- состояние объявляется через `aria-expanded`;
- Enter и Space сворачивают или разворачивают группу;
- в mini-sidebar группы принудительно считаются открытыми, чтобы не скрывать пункты меню;
- состояние хранится для текущего браузера и пользователя рабочего места.

Ключ localStorage:

```text
collegePortal.navigation.sections.v1
```

При изменении состава меню старая схема может быть заменена новым versioned key.

## Dashboard layout

Dashboard использует персональные настройки виджетов и локальный fallback. Для обычного просмотра применяется masonry-like раскладка на CSS columns: карточки занимают свободное вертикальное пространство и не оставляют крупных пустых зон из-за высоты соседнего виджета. В режиме настройки сохраняется grid-раскладка с drag-and-drop, чтобы порядок и размер виджетов можно было редактировать предсказуемо.

Поддерживаемые размеры виджетов:

- `S` — компактный блок;
- `M` — стандартный блок;
- `L` — широкий блок в режиме настройки;
- `XL` — full-width блок в режиме настройки.

Ключ локального fallback-layout:

```text
collegePortal.dashboard.layout.v2.<dashboardType>
```

Payload хранит `version`, `dashboardType`, `widgets` и `savedAt`. Для каждого виджета сохраняются `id`, `order`, `size` и `visible`. Кнопка “Стандартный вид” сбрасывает backend-layout и удаляет локальный fallback.

## Поведение на разных ширинах

### 1920 px

- sidebar виден;
- таблица и карточка стоят в две колонки;
- таблица должна показывать большую часть колонок без горизонтальной прокрутки;
- карточка остается в диапазоне `380–420 px`.

### 1600 px

- sidebar виден;
- layout остается двухколоночным;
- таблица занимает оставшееся место;
- при большом количестве колонок допускается внутренняя горизонтальная прокрутка таблицы.

### 1366 px

- для страниц с широкими таблицами используется одна колонка: сначала таблица, ниже карточка;
- это предпочтительнее, чем сжимать таблицу до нечитаемого состояния;
- правая карточка не должна оставаться поверх таблицы или визуально перекрывать последние колонки;
- таблица может иметь горизонтальную прокрутку внутри своей области, но не должна уходить под карточку.

### Узкие экраны

При ширине viewport до `1440 px` рабочие страницы с широкими таблицами могут переходить в одну колонку:

- сначала таблица;
- ниже карточка выбранной записи;
- карточка занимает всю доступную ширину.

## Запрет на overlay-карточки

Нельзя:

- размещать правую карточку через `position: absolute` поверх таблицы;
- давать таблице ширину, из-за которой она уходит под карточку;
- использовать отрицательные отступы для совмещения карточки и таблицы;
- скрывать последние колонки таблицы под правой панелью;
- решать проблему наложения только увеличением `z-index`.

## Правила для будущих разделов

Новые CRUD-разделы должны повторять принцип разделов “Студенты” и “Группы”:

- фильтры сверху;
- действия над таблицей в toolbar;
- таблица слева;
- карточка выбранной записи справа;
- карточка 380–420 px;
- таблица прокручивается внутри своей области;
- при недостатке ширины карточка переносится под таблицу.

Если раздел требует больше места для карточки, сначала нужно пересмотреть состав карточки и вкладки, а не увеличивать правую колонку за счет читаемости таблицы.

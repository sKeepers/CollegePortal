# Responsive Workspace CollegePortal

## Назначение

Responsive Workspace Foundation описывает единые правила адаптации рабочего интерфейса CollegePortal под разные размеры экранов.

Цель — сохранить рабочий характер интерфейса на обычных desktop-мониторах, ultrawide-экранах и мобильных устройствах, не меняя backend, API и бизнес-логику модулей.

## Breakpoints

| Код | Размер | Назначение |
| --- | --- | --- |
| `XS` | `< 600 px` | мобильный экран |
| `SM` | `600-1023 px` | крупный мобильный экран или небольшой планшет |
| `MD` | `1024-1439 px` | малый desktop или ноутбук |
| `LG` | `1440-1919 px` | стандартный desktop |
| `XL` | `1920-2559 px` | широкий desktop |
| `XXL` | `>= 2560 px` | ultrawide и большие рабочие станции |

В коде breakpoints определяются в `frontend/src/services/layoutService.js`.

## Layout Service

`frontend/src/services/layoutService.js` предоставляет:

- текущий breakpoint;
- ширину окна;
- высоту окна;
- признак ultrawide-экрана;
- признак мобильного экрана;
- производные признаки tablet/desktop.

Сервис не хранит пользовательские настройки. Он только отражает текущее состояние viewport.

## Workspace Store

`frontend/src/stores/workspace.js` хранит настройки рабочего пространства:

- ширину бокового меню;
- свернуто ли меню;
- отображение правой панели;
- плотность интерфейса;
- режим рабочего пространства.

Настройки сохраняются в `localStorage` по ключу `collegePortal.workspace.settings`.

## Плотность интерфейса

Поддерживаются два режима:

- `comfortable` — стандартная плотность, используется по умолчанию;
- `compact` — уменьшенные отступы, более плотные панели и таблицы.

Плотность не должна менять состав данных или доступные действия. Она влияет только на визуальные интервалы и высоту рабочих элементов.

## Режимы рабочего пространства

### Default

Обычный рабочий режим:

- левое меню видно на desktop;
- правая карточка показывается, если страница ее использует;
- таблица и карточка размещаются по правилам `docs/LAYOUT_GUIDELINES.md`.

### Focus

Режим концентрации:

- правая панель может скрываться;
- вторичные элементы могут быть уменьшены или скрыты;
- основная таблица или рабочая область получает больше места.

### Wide

Режим для широких экранов:

- используется больше рабочей ширины;
- Dashboard получает больше колонок;
- таблицы и рабочие доски могут показывать больше данных без горизонтальной прокрутки.

### Presentation

Режим презентации:

- боковое меню может быть скрыто;
- интерфейс должен показывать ключевую информацию крупнее и спокойнее;
- режим предназначен для демонстрации, а не для массового ввода данных.

На этапе GUI-011 подготовлена инфраструктура режимов. Полные пользовательские переключатели и отдельные настройки экранов можно добавлять позже.

## Dashboard

Dashboard адаптирует количество колонок:

- `1366 px` — 2 колонки;
- `1920 px` — 3 колонки;
- `2560 px` и шире — 4 колонки.

Верхний блок статистики остается отдельным широким блоком. Виджеты должны быть независимыми и не содержать бизнес-логику, чтобы сетка могла свободно перестраиваться.

## Рабочие страницы

Для страниц `Students`, `Groups`, `Schedule`, `Journal` действует общий принцип:

- основная рабочая область слева;
- карточка выбранной записи справа;
- карточка не должна перекрывать таблицу или журнал;
- на узких экранах карточка переносится ниже основной области;
- в режиме Focus правая панель может скрываться.

Эти страницы получают breakpoint-классы через `AppPage` и общий workspace-класс из `AppLayout`.

## Рекомендации для новых страниц

- Использовать `AppPage`, чтобы страница автоматически получила breakpoint-классы.
- Не вычислять ширину страницы вручную внутри компонента.
- Не позиционировать правую карточку через overlay.
- Для layout “таблица + карточка” использовать grid-структуру из `docs/LAYOUT_GUIDELINES.md`.
- На ultrawide не растягивать бесконтрольно текстовые строки; увеличивать количество колонок или ширину таблиц осознанно.
- Мобильную адаптацию проектировать как последовательность рабочих блоков: фильтры, таблица/список, карточка.

## Ограничения GUI-011

- Не добавляется экран пользовательских настроек workspace.
- Не меняется backend, база данных и API.
- Не меняется бизнес-логика студентов, групп, расписания и журнала.
- Режимы `Focus`, `Wide`, `Presentation` подготовлены инфраструктурно и будут развиваться позже.

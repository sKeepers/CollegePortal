# Починка карточек преподавателя на боевом портале

Найдено 17.08.2026 владельцем: в разделе «Преподаватели» вместо ФИО, должности и отделения — вопросительные знаки. Разбор показал **две разные неисправности** в одних и тех же двух карточках. Одна чинится данными, вторая уже исправлена в коде.

Реальных ФИО здесь нет намеренно: карточки различаются по телефону, он уцелел.

## Что случилось

**Первое: кириллица уничтожена.** Каждый русский символ заменён одним знаком «?» — признак преобразования в однобайтовую кодировку, где кириллицы нет. Цифры телефонов уцелели, потому что есть в любой кодировке.

Это **данные, а не портал**. Замер на стенде DEV: 73 карточки преподавателей, знаков «?» ноль, кириллица по два байта на символ. В бэкенде нет ни одного `mb_convert_encoding` или `iconv`. Если бы портал портил вывод, «?» стояли бы на всех страницах — а раздел «Люди» показывает те же девять человек правильно.

Источник — заведение карточек 16.08.2026 через `POST /api/teachers` с рабочей станции Windows. Русский текст, переданный аргументом командной строки, преобразуется в кодовую страницу консоли, и непредставимое становится «?» **до отправки запроса**. Портал получил уже испорченное.

**Второе: карточки не связаны с карточками людей.** В «Людях» у всех девяти значки профилей — «Сотрудник» и «Пользователь», значка «Преподаватель» нет ни у кого. Значит, у обеих карточек преподавателя `person_id` пуст.

Это была неисправность кода: заведение преподавателя не заводило и не привязывало человека, хотя правка карточки написана верно — но её ветка работает только при связанном человеке, а его не было. **Исправлено `325e2b4da`**: человек теперь заводится всегда, как при зачислении студента. На уже созданные карточки правка не действует задним числом — их надо связать.

## Порядок починки

Три шага, порядок важен: связывание ищет человека по СНИЛС, телефону, почте либо по ФИО с датой рождения. Пока ФИО состоят из «?», работает только совпадение по телефону — а после первого шага их станет три.

### 1. Вписать ФИО, должность и отделение заново

Раздел «Преподаватели» → карточка → правка → сохранить. Обе карточки.

Должность и отделение — поля самой карточки преподавателя, в карточке человека их нет; правильные значения знает только владелец.

После этого экран читается. Оставшиеся два шага чинят связь.

### 2. Посмотреть план связывания

```bash
php artisan person:link-existing --dry-run
```

**Ожидается ровно две связи и ноль созданий.** Если `would_create` больше нуля — остановиться: команда не нашла совпадения и собирается завести лишнего человека. Показать вывод разработчику, а не применять.

Если в выводе есть раздел про неоднозначные совпадения — тоже остановиться: две подходящие карточки человека значат, что выбирать должен человек.

### 3. Применить и обновить копии

```bash
php artisan person:link-existing --apply
```

Затем открыть обе карточки в разделе «Люди» и **сохранить без правок**. Сохранение раскладывает общие данные по всем профилям, и копия ФИО в карточке преподавателя обновляется из карточки человека — с этого момента расходиться им нечем.

## Проверка

- В «Людях» у обоих появился значок «Преподаватель».
- В «Преподавателях» ФИО, должность и отделение читаются.
- Правка ФИО в карточке человека меняет его и в списке преподавателей.

## Чтобы не повторилось

**Русский текст не передавать аргументом командной строки с рабочей станции Windows.** Заводить через интерфейс портала либо слать тело запроса файлом — `--data-binary @файл.json`, файл в UTF-8: тогда консоль к содержимому не прикасается.

Заведение преподавателя штатной командой по-прежнему не делается: `portal:staff-account --role=teacher` создаёт кадровую карточку, но не карточку преподавателя. Это отдельная задача.

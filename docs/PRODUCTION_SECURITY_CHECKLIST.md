# PRODUCTION_SECURITY_CHECKLIST

Дата: 09.07.2026.  
Окружение подготовки: DEV `/srv/college-dev`.  
PROD: не изменялся.

## Назначение

Документ фиксирует обязательные проверки безопасности перед будущим переносом CollegePortal в production. Это не инструкция на автоматический деплой: каждый пункт должен быть подтвержден ответственным администратором перед фактическим переключением PROD.

## 1. Laravel environment

- [ ] `APP_ENV=production`.
- [ ] `APP_DEBUG=false`.
- [ ] `APP_KEY` задан и не совпадает с DEV/TEST.
- [ ] `.env` не находится в Git.
- [ ] `LOG_LEVEL` не раскрывает лишние details пользователю.
- [ ] Ошибки API не возвращают stack trace во frontend.

## 2. Безопасные пароли и учетные записи

- [ ] Все demo-пароли заменены.
- [ ] Пароль `demo12345` отсутствует у production-пользователей.
- [ ] Учетная запись администратора имеет уникальный сложный пароль.
- [ ] Неиспользуемые UAT/demo users заблокированы или удалены.
- [ ] Проверены роли `admin`, `director`, `deputy`, `study`, `admission`, `teacher`, `student`, `security`.
- [ ] Для персонала определены реальные ответственные роли.

## 3. Запрет demo reset в production

- [ ] Очистка demo-data запрещена при `APP_ENV=production`.
- [ ] Раздел `/admin/data-management` проверен на production-защиту.
- [ ] Скрипты/seeders не выполняют destructive actions без явного подтверждения.
- [ ] У администратора есть инструкция: не запускать demo seed/clear на PROD.

## 4. Storage permissions

- [ ] `storage/` и `bootstrap/cache/` доступны для записи backend-контейнеру.
- [ ] Права не выставлены чрезмерно широко, например `777` без необходимости.
- [ ] `public/storage` symlink создан корректно, если используются публичные фото.
- [ ] Import files хранятся не в публичной директории.
- [ ] Логи не доступны через web.

## 5. Backup before deploy

- [ ] Перед деплоем создан backup файлов проекта.
- [ ] Перед деплоем создан backup PostgreSQL.
- [ ] Backup сохранен в `/srv/backups/college-portal/` или другом утвержденном каталоге.
- [ ] Проверено, что backup можно восстановить.
- [ ] Зафиксированы версии commit/hash и timestamp backup.

## 6. HTTPS / reverse proxy

- [ ] Внешний доступ идет только по HTTPS.
- [ ] HTTP либо отключен, либо делает redirect на HTTPS.
- [ ] TLS certificate валиден.
- [ ] Reverse proxy передает корректные headers: `X-Forwarded-Proto`, `X-Forwarded-For`, `Host`.
- [ ] Laravel trust proxies настроен, если приложение за Nginx/reverse proxy.

## 7. CORS

- [ ] Разрешены только production-домены CollegePortal.
- [ ] DEV origin не разрешен в PROD без необходимости.
- [ ] `Access-Control-Allow-Credentials` используется только если это действительно нужно.
- [ ] Проверены API-запросы frontend -> backend из production domain.

## 8. Session/token lifetime

- [ ] Token lifetime согласован с регламентом колледжа.
- [ ] Logout инвалидирует токен.
- [ ] Старые DEV/UAT токены не действуют в PROD.
- [ ] Для мобильного кабинета отдельно согласован срок жизни сессии.
- [ ] Для проходной учтен режим длительной рабочей смены.

## 9. Upload limits

- [ ] Ограничен размер import CSV/XLSX.
- [ ] Ограничен размер фото Person.
- [ ] Nginx `client_max_body_size` согласован с Laravel validation.
- [ ] Разрешены только ожидаемые расширения файлов.
- [ ] XLSX импорт не выполняется для неизвестно больших файлов без регламента.

## 10. Audit enabled

- [ ] Audit log включен для auth, users, roles, import, QR, demo-data и административных действий.
- [ ] Раздел `/admin/audit` доступен только уполномоченным ролям.
- [ ] Audit logs не редактируются через API.
- [ ] Определена политика хранения audit logs.
- [ ] Проверено, что импорт реальных данных фиксируется в audit.

## 11. Import file retention

- [ ] Определен срок хранения загруженных import-файлов.
- [ ] Определен срок хранения preview rows и validation errors.
- [ ] Есть процедура очистки старых файлов импорта.
- [ ] Экспорты с персональными данными не остаются в публичных директориях.
- [ ] Ответственный понимает, где хранятся реальные CSV/XLSX после загрузки.

## 12. QR token safety

- [ ] QR содержит только token, без ФИО, email, телефона и других персональных данных.
- [ ] Token достаточно случайный/уникальный.
- [ ] Отозванный QR не дает allowed scan.
- [ ] Expired/suspended QR корректно отклоняется.
- [ ] Доступ к выпуску/отзыву QR ограничен отдельными ролями.
- [ ] Срок действия QR согласован через настройки колледжа.

## 13. Roles/users review

- [ ] Проверен список production-пользователей.
- [ ] У каждого пользователя есть минимально необходимая роль.
- [ ] Уволенные/неактивные сотрудники заблокированы.
- [ ] Студенческие учетные записи не имеют административных прав.
- [ ] Сотрудник проходной имеет доступ только к нужным access-разделам.
- [ ] Пользователи приемной комиссии не получают лишний доступ к системным настройкам.

## 14. Public settings review

- [ ] Проверены публичные настройки `/api/settings/public`.
- [ ] Публичные настройки не содержат секретов.
- [ ] Название колледжа, адрес, телефон, сайт и branding корректны.
- [ ] В public settings нет внутренних URL, паролей, токенов, ключей или email-ящиков с паролями.

## 15. Final go/no-go

Перед переносом в PROD должны быть выполнены:

- [ ] `php artisan test` успешно.
- [ ] `npm run build` успешно.
- [ ] DEV smoke-check пройден.
- [ ] Backup создан и проверен.
- [ ] Rollback plan готов.
- [ ] Ответственный подтверждает go-live.

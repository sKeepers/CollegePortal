# Документы абитуриента Admissions Foundation

Документ фиксирует реализацию BACK-005: структурированные идентификационные сведения, документы об образовании, private files и расчет готовности заявления. Это foundation-слой новой приемной комиссии; legacy-раздел `/admissions` и старые `applicant-applications` не изменяются.

BACK-005.1 укрепляет эту основу без повторной реализации BACK-005: добавляет явную связь заявления с конкретными версиями документов, безопасное версионирование реквизитов, дополнительные XSD-поля документа об образовании и проверку словарных соответствий ФИС через существующий `fis_external_mappings`.

## Модель

### СНИЛС

СНИЛС хранится на уровне `Person`, потому что это общий идентификатор человека, а не отдельного заявления.

| Поле | Назначение |
| --- | --- |
| `people.snils` | нормализованный СНИЛС для внутренней работы |
| `people.snils_hash` | SHA-256 нормализованного СНИЛС для поиска дублей без раскрытия значения |

API-ресурсы по умолчанию возвращают `snils_masked` и `has_snils`. Полное значение доступно только пользователям с правом `admissions.document.download_sensitive` или административным правом на обновление Person.

### Связь заявления с документами

Таблица `admission_application_documents` фиксирует, какие версии документов используются конкретным foundation-заявлением:

- `application_id`;
- `identity_document_id`;
- `education_document_id`;
- `linked_by`;
- `linked_at`;
- `metadata`.

`GET /api/admissions/applications/{application}/documents` показывает текущую фиксацию и не создает запись в таблице. При регистрации заявления сервис автоматически фиксирует текущие основные документы, если явная связь не была задана ранее.

После регистрации заявление продолжает ссылаться на те же записи документов. Если позже у Applicant появляется новый паспорт или новый документ об образовании, readiness зарегистрированного заявления остается привязанным к старой версии.

### Версионирование

PATCH разделяет изменения:

- служебные изменения проверки, например `verification_status` и `verification_comment`, могут обновляться на месте;
- изменение реквизитов документа, закрепленного за зарегистрированным заявлением, создает новую версию;
- старая версия получает `replaced_at` и `replaced_by_document_id`, но остается доступной для исторического заявления;
- файлы старой версии не копируются автоматически в новую версию;
- архивирование документа или файла, закрепленного за зарегистрированным заявлением, запрещено обычным operation flow.

Это сохраняет воспроизводимость зарегистрированного заявления без snapshot всех реквизитов.

### Файлы документов

Таблица `admission_document_files` хранит metadata private-файлов и связь с документом:

- `applicant_id`;
- `application_id` nullable;
- `identity_document_id` nullable;
- `education_document_id` nullable;
- `category`;
- `original_name`;
- `generated_name`;
- `storage_path`;
- `mime_type`;
- `extension`;
- `size_bytes`;
- `sha256`;
- `uploaded_by`;
- `uploaded_at`;
- `archived_at`.

Файлы сохраняются на `Storage::disk('local')`, то есть в private storage приложения. API-ресурсы не отдают `storage_path`. Удаление на этом этапе является архивированием metadata; физический файл не удаляется.

## Готовность заявления

Расчет разделяет три уровня:

| Уровень | Условие |
| --- | --- |
| `internal_complete` | есть основной документ личности, СНИЛС, основной документ об образовании, файл личности и файл образования |
| `review_complete` | `internal_complete=true` и оба документа имеют статус `verified` |
| `fis_data_ready` | пока всегда `false`, потому что XML-маппинг и ФИС-пакет не входят в BACK-005 |

Регистрация заявления остается обратно совместимой. Жесткая проверка документов включается только при `confirm_required_fields=true`.

С BACK-005.1 readiness конкретного заявления использует `admission_application_documents`, если документы зафиксированы. Для черновиков без фиксации используется fallback на текущие основные документы Applicant без записи побочных данных в БД.

FIS readiness не считает внутренние ID справочников кодами ФИС. Сопоставления ищутся в `fis_external_mappings` по `ReferenceItem::class`, `entity_id`, `external_type=fis:<dictionary>` и `environment=test`. При отсутствии mapping возвращается blocker с машинным кодом и русским сообщением.

## Безопасность

- Скан-копии хранятся только в private storage.
- `storage_path` не возвращается в API.
- Полные серия, номер и СНИЛС маскируются в ресурсах без sensitive permission.
- В audit не пишутся `snils`, `snils_hash`, `series`, `number`, `number_hash`, `storage_path`, `stored_path`, `fis_raw_data`.
- Повторная загрузка того же файла к тому же документу отклоняется по `sha256`.
- Разрешены только `PDF`, `JPG`, `JPEG`, `PNG` до 15 МБ.
- Реквизиты и файлы документа, закрепленного за зарегистрированным заявлением, не изменяются незаметно: реквизиты создают новую версию, файлы блокируются для изменения.

## Ограничения BACK-005

- Не реализуется frontend.
- Не реализуется генерация XML.
- Не выполняется XSD validation пакета заявления.
- Не выполняется SOAP, Gateway, Import, Validate, Delete или отправка в ФИС.
- Legacy `/admissions` не мигрируется и не смешивается с Admissions Foundation.

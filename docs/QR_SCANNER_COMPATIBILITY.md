# QR Scanner Compatibility

## Назначение

`QR-004` фиксирует требования к QR-пропускам CollegePortal для надежного чтения обычным USB HID QR-сканером.

## Найденная причина риска

До доработки QR отдавался только как SVG и отображался в интерфейсе сравнительно небольшим размером. Также проходная принимала только точное значение `token`, поэтому сканеры, настроенные на префикс, CR/LF, Tab или пробелы по краям, могли давать отказ.

Дополнительно QR был с уровнем коррекции L. Для физических сканеров и печати выбран более устойчивый профиль.

## Точное содержимое QR

QR содержит только чистый ASCII token цифрового пропуска.

Пример формата:

```text
123e4567-e89b-12d3-a456-426614174000
```

В QR не записываются:

- ФИО;
- email;
- телефон;
- группа;
- роль;
- JSON;
- URL.

Для входа через проходную поддерживаются два формата:

```text
<token>
CP1:<token>
```

При сканировании система удаляет только пробелы, CR, LF и Tab по краям строки. Внутренние символы token не изменяются.

## Параметры генерации

- QR Version 3;
- byte mode;
- Error Correction Level M;
- quiet zone: 4 модуля;
- черные модули на белом фоне;
- без прозрачности;
- без логотипов;
- без градиентов;
- целочисленный масштаб;
- SVG/PNG размер: 370×370 px;
- рекомендуемый экранный размер: не менее 280×280 px;
- рекомендуемый печатный размер: не менее 30×30 мм.

## API

```text
GET /api/digital-identities/{id}/qr?format=svg
GET /api/digital-identities/{id}/qr?format=png
```

Оба формата кодируют одно и то же значение: `token`.

## Интерфейс

### `/identity/digital-passes`

Добавлено:

- белая квадратная подложка QR;
- кнопка `Открыть QR крупно`;
- кнопка `Скачать PNG`;
- кнопка `Показать значение QR` для диагностики;
- пояснение, что QR содержит только token.

### `/m/student/pass`

QR отображается на белом фоне, без тени вокруг кода, с достаточной рамкой и размером для чтения с экрана телефона.

### `/access/gate`

Добавлен режим `Диагностика сканера`:

- сырое считанное значение;
- нормализованное значение;
- длина строки;
- первый и последний символ;
- наличие CR/LF/Tab;
- был ли Enter;
- интервалы между вводимыми символами.

Поддерживается опция `Tab завершает скан` для сканеров, настроенных на Tab вместо Enter.

### `/access/scanner-test`

DEV-страница только для администратора. Показывает эталонный QR, ожидаемое значение и результат сравнения со считанной строкой.

## Инструкция физической проверки

1. Открыть `/identity/digital-passes`.
2. Выбрать активный пропуск.
3. Нажать `Открыть QR крупно`.
4. Отсканировать QR физическим USB HID-сканером в текстовый редактор.
5. Проверить, что результат выглядит как UUID/token без ФИО и без URL.
6. Открыть `/access/scanner-test`.
7. Отсканировать эталонный QR в поле проверки.
8. Убедиться, что отображается `Совпадает`.
9. Открыть `/access/gate`.
10. Включить `Диагностика сканера`.
11. Отсканировать активный QR.
12. Проверить, что проход разрешен, а диагностика показывает Enter или настроенный Tab.
13. Если сканер добавляет Tab вместо Enter, включить `Tab завершает скан`.
14. Если сканер добавляет префикс, использовать `CP1:`; другие префиксы не поддерживаются.

## Настройки сканера

Рекомендуемые настройки HID-сканера:

- режим клавиатуры USB HID;
- кодировка ASCII/UTF-8;
- suffix: Enter / CR / LF;
- префикс: пусто или `CP1:`;
- без автоматического добавления кавычек;
- без преобразования регистра;
- без вставки URL-префикса.

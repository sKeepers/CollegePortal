# Демонстрационные данные DEV

## Назначение

`DemoDataSeeder` подготавливает DEV-стенд CollegePortal к демонстрации без использования реальных персональных данных.

Демо-набор нужен для проверки Dashboard, расписания, журнала, проходной, QR-пропусков, посещаемости и оценок в условиях, похожих на рабочий процесс колледжа.

## Состав

Seeder создает или обновляет:

- около 600 студентов;
- около 70 преподавателей;
- связанные записи `people` для студентов и преподавателей;
- кадровые записи `employees` для преподавателей;
- около 30 учебных групп;
- образовательные программы и специальности;
- дисциплины;
- аудитории;
- расписание на учебную неделю;
- посещаемость;
- оценки;
- цифровые пропуска;
- события проходной за сегодня;
- демонстрационные заявления приемной комиссии.

## Безопасность

Демо-данные не содержат реальные ФИО, телефоны, email, паспортные данные, СНИЛС или адреса.

ФИО синтетические и формируются детерминированно из демонстрационных списков фамилий, имен и отчеств. Seeder избегает массового повторения одной и той же комбинации ФИО, чтобы таблицы студентов, преподавателей, людей и сотрудников выглядели как рабочий контур колледжа, а не как техническая заглушка.

Используемые email относятся к служебным доменам:

- `college-portal.local`;
- `demo.college.local`.

Демо-пароль задается через переменную окружения:

```env
DEMO_USER_PASSWORD=test1234
```

Пароли не сохраняются в документацию, логи или Git.

## Создание

Через API администратора:

```text
POST /api/admin/demo-data/create
```

Через Artisan:

```bash
php artisan db:seed --class=Database\\Seeders\\DemoDataSeeder --force
```

## Очистка

Через API администратора:

```text
POST /api/admin/demo-data/clear
```

Очистка удаляет только известный демо-набор: демо-людей, демо-сотрудников, демо-студентов, демо-преподавателей, демо-группы, демо-расписание, оценки, посещаемость, цифровые пропуска, события проходной и демо-заявления.

Администратор `admin@college-portal.local` не удаляется.

## Проверка

После создания демо-данных Dashboard должен показывать ненулевые показатели:

- студенты;
- люди;
- преподаватели;
- сотрудники;
- занятия сегодня;
- входы сегодня;
- сейчас в колледже;
- оценки и посещаемость в карточках студентов.

Посещаемость строится по событиям проходной текущего дня:

- часть людей приходит до первой пары;
- часть опаздывает на ограниченное число минут;
- часть не имеет входа и отображается как отсутствующая;
- часть имеет выход, чтобы отчеты показывали не только открытые входы.

Время входа в API посещаемости отдается в локальном формате без UTC-сдвига, чтобы колонка "Первый вход" визуально совпадала с расчетом опоздания от "Первой пары".

Для проверки QR:

1. войти как `student@college-portal.local`;
2. открыть `https://192.168.34.114:5443/m/student/pass`;
3. убедиться, что QR обновляется каждые 30 секунд;
4. войти как администратор или сотрудник проходной;
5. открыть `https://192.168.34.114:5443/access/mobile-scanner`;
6. считать QR.

## Ограничения

- Демо-набор предназначен только для DEV.
- Не запускать очистку демо-данных в production.
- Для доверенного HTTPS на телефонах требуется установить DEV root CA или использовать публичный домен с доверенным сертификатом.

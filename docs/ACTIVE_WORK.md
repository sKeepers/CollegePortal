**Что делает система теперь.**

- Студент без заявления в приёмной комиссии может иметь паспорт и документ об образовании: `POST api/students/{id}/identity-documents` и `.../education-documents`, `applicant_id` остаётся пустым.
- Человек заводится для каждого студента, иначе документ некуда прикрепить. При пустом СНИЛС система ищет совпадения по ФИО и дате рождения и возвращает их в `warnings.duplicate_candidates` — предупреждение, а не автосвязывание.
- Реквизиты паспорта с формы студента сохраняются как документ человека; новая версия документа создаётся, только если реквизиты действительно изменились.
- Реестр показывает признак «Полная / Неполная» и умеет фильтровать `completeness=incomplete`. Карточка студента показывает, чего не хватает, и позволяет добавить документ об образовании.
- Жёсткие блокировки: `mark-exported` в ФИС ГИА и ФРДО — только для проверенного пакета; неполная карточка делает запись пакета невалидной; диплом и приложение к диплому не выдаются; номер приказа о зачислении нельзя записать или изменить.
- Импорт студентов принимает паспорт и документ об образовании, но не требует их: строка без них не ошибка. Обе точки загрузки — «Универсальный импорт» и кнопка в реестре — заводят человека и кладут документы ему, поэтому один и тот же файл даёт одинаковый результат. Выгрузка отдаёт те же колонки.

### Сборка XML по официальной XSD — сделано 09.08.2026, ветка `feature/fis-xml-official-xsd`

`pending-official-spec` снят: версия схемы по умолчанию — **4.9 от 15.06.2026**, XSD подключена, сборка XML работает и проверяется по официальному файлу. Соответствие полей — [FIS_DATA_MAPPING.md](FIS_DATA_MAPPING.md), контур — [FIS_OUTBOUND_PACKAGES.md](FIS_OUTBOUND_PACKAGES.md).

**Главное, что выяснилось при чтении схемы: раздела для результатов ГИА колледжа в методе импорта нет.** Метод принимает приёмную кампанию — кампании, объём приёма, конкурсы, образовательные программы, заявления, приказы. «ГИА» в названии системы относится к ЕГЭ и ОГЭ, их вносит РЦОИ. Единственное упоминание в схеме — справки ГИА, приложенные абитуриентом к заявлению. Пакет ГИА портала остаётся внутренним отчётом; сборка XML по нему отклоняется с этим объяснением, а не выдумывает раздел. Работа прошлой сессии по пакету ГИА не пропала: она про внутренний отчёт и полноту карточек, и это по-прежнему верно.

**Второе, чего не ожидали: официальную XSD libxml не компилирует.** Семь `xs:pattern` записаны в синтаксисе .NET с опережающей проверкой `(?!\s*$)`, которой в XSD 1.0 нет; отказ идёт по всему файлу целиком, «Invalid Schema». `FisXsdSchema` подменяет их равнозначным выражением XSD 1.0 в памяти, официальный файл не трогается, подстановки уходят в событие проверки пакета.

# Design System CollegePortal

Дата: 2026-06-30

Design System фиксирует визуальные правила CollegePortal для нового Quasar GUI. Документ опирается на:

- `docs/UI_FOUNDATION.md` — базовые UI-компоненты и правила CRUD-страниц;
- `docs/LAYOUT_GUIDELINES.md` — рабочая компоновка страниц;
- `docs/RESPONSIVE_WORKSPACE.md` — breakpoints и адаптивное поведение.

Цель дизайн-системы — сохранить единый, спокойный и плотный интерфейс для сотрудников колледжа, близкий по характеру к рабочим системам учета и управления учебным процессом.

## Логотип

CollegePortal использует официальный черно-белый логотип Ставропольского краевого колледжа искусств.

Исходник:

- `docs/logo/Logo_SKKI_чб.jpg`

Frontend-копия:

- `frontend/public/brand/logo-skki-bw.jpg`

Правила:

- не придумывать новый знак;
- не менять форму знака;
- не добавлять оранжевую, желтую или декоративную подложку;
- не искажать пропорции;
- использовать техническое масштабирование только для нужного размера иконки;
- на темном sidebar использовать черный знак на белой компактной плашке;
- не использовать знак как декоративный фон.

## Favicon и PWA-иконки

Файлы:

- `frontend/public/favicon.ico`;
- `frontend/public/favicon.svg`;
- `frontend/public/apple-touch-icon.png`;
- `frontend/public/icons/icon-192.png`;
- `frontend/public/icons/icon-512.png`;
- `frontend/public/manifest.webmanifest`.

Правила:

- favicon и PWA-иконки должны строиться из официального черно-белого знака;
- фон favicon/PWA-иконок — белый или прозрачный, если читаемость сохранена;
- `theme_color`: `#0f172a`;
- `background_color`: `#ffffff`;
- title страницы: `CollegePortal`.

## Дополнительные цвета

Дополнительные цвета должны использоваться функционально, а не декоративно:

- `#f8fafc` — мягкий фон строк, списков и вложенных светлых областей;
- `#eff6ff` — информационная подсветка;
- `#f1f5f9` — нейтральный фон inactive/empty;
- `#fff7ed` — предупреждения;
- `#fff1f2` — ошибки;
- `#ecfdf5` — успешные состояния.

Не делать интерфейс одноцветным. Основной характер: темный sidebar, светлая рабочая область, спокойные функциональные акценты.

## Цвета статусов

| Статус | Текст | Фон | Применение |
| --- | --- | --- | --- |
| Успех / активно | `#047857` | `#ecfdf5` | активный студент, выполнено, корректно |
| Внимание | `#c2410c` | `#fff7ed` | требует проверки, предупреждение |
| Ошибка | `#991b1b` | `#fff1f2` | отклонено, ошибка API, критичная проблема |
| Информация | `#1d4ed8` | `#eff6ff` | план, справочная отметка |
| Неактивно / архив | `#64748b` | `#f1f5f9` | архив, неактивные записи |

Статус нельзя показывать только цветом: нужен текст через `AppStatusBadge`.

## Типографика

Шрифт:

```css
Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif
```

Правила:

- не использовать отрицательный letter-spacing;
- не масштабировать шрифт через viewport width;
- внутри панелей и карточек не использовать hero-size заголовки;
- служебные подписи должны быть компактными, но читаемыми.

## Размеры шрифтов

| Элемент | Размер |
| --- | ---: |
| Заголовок страницы | `20-24px` |
| Заголовок панели | `16-18px` |
| Основной текст | `14px` |
| Таблицы | `12-13px` |
| Вторичные подписи | `12-13px` |
| Служебные подписи | `11-12px` |

## Отступы

Базовая сетка:

- `4px` — минимальный шаг;
- `8px` — компактные промежутки;
- `12px` — внутренний отступ компактных блоков;
- `16px` — панели и карточки;
- `22-24px` — рабочая область desktop.

Правила:

- рабочий интерфейс должен быть плотным;
- не добавлять большие декоративные промежутки;
- фильтры, toolbar и таблица должны быть визуально связаны;
- карточка справа должна иметь достаточно воздуха внутри секций, но не быть рыхлой.

## Скругления

- обычные панели и карточки: до `8px`;
- кнопки и inputs: следовать Quasar-теме, без чрезмерной округлости;
- статусные бейджи: компактные pill/rounded, если это не ломает плотность;
- не делать большие радиусы у рабочих таблиц и форм.

## Тени

Тени использовать минимально:

- основной интерфейс строится на границах и фоне, а не на тяжелых тенях;
- допустима легкая тень для dropdown, modal, overlay поиска;
- карточки рабочих страниц не должны выглядеть как плавающие marketing-card.

## Кнопки

Типы:

- primary — главное действие страницы;
- secondary/flat — вторичные действия;
- danger — удаление и необратимые операции;
- icon button — компактные действия в таблицах и toolbar.

Правила:

- текст кнопки должен быть действием: `Создать`, `Сохранить`, `Удалить`, `Импорт`, `Экспорт`;
- опасные действия требуют подтверждения;
- loading и disabled состояния обязательны;
- иконки Lucide использовать там, где они ускоряют распознавание;
- не перегружать toolbar яркими кнопками.

## Формы

Формы строятся на Quasar inputs и `AppFormSection`.

Правила:

- группировать поля по смыслу;
- показывать ошибки рядом с полем;
- обязательные поля должны быть очевидны;
- длинные формы не помещать в маленькие modal;
- действия формы держать внизу секции;
- не смешивать ввод, фильтры и read-only показатели в одном визуальном блоке.

## Таблицы

Таблицы строятся на `AppTable` поверх Quasar `QTable`.

Правила:

- короткие заголовки колонок;
- действия в последней колонке;
- строковые действия компактные;
- главный идентификатор записи может быть ссылкой на карточку;
- статус показывать через `AppStatusBadge`;
- выбранная строка должна быть заметна;
- пагинация на русском: `Записей на странице:`;
- варианты размера страницы: `10`, `20`, `50`, `Все`;
- настройки таблиц сохранять через `frontend/src/services/tableSettings.js`;
- горизонтальная прокрутка должна быть внутри таблицы.

## Карточки

Карточки строятся через `AppCard` и detail panel компонентов.

Правила:

- карточка показывает детали выбранной записи, а не заменяет таблицу;
- шапка карточки: название/ФИО, статус, ключевой контекст;
- быстрые показатели размещаются выше вкладок;
- сложные карточки используют вкладки;
- секции должны быть простыми, без лишних вложенных рамок;
- длинные значения переносятся, не выходят за пределы панели;
- правая карточка не должна перекрывать таблицу.

## Бейджи статусов

Использовать `AppStatusBadge`.

Правила:

- цвет + текст;
- статус должен быть понятен без легенды;
- не использовать слишком много разных оттенков для одной сущности;
- одинаковые статусы во всех разделах должны выглядеть одинаково.

## Модальные окна

Использовать для:

- подтверждения удаления;
- коротких действий;
- небольших справок;
- выбора одного параметра.

Не использовать для:

- длинных форм;
- больших таблиц;
- карточки студента/группы/занятия;
- рабочих процессов, где пользователь должен сравнивать данные.

## Уведомления

- успешное действие — короткий toast;
- ошибка API — `AppErrorBanner` в контексте страницы или toast, если ошибка локальная;
- warning должен говорить, что именно нужно исправить;
- loading не должен сдвигать layout;
- глобальное сообщение загрузки располагается в верхней панели рядом с действиями, а не отдельной строкой над контентом.

## Левое меню

Sidebar:

- фон `#111827`;
- ширина desktop: `286px`;
- логотип СККИ на белой компактной плашке;
- группы меню с короткими заголовками;
- активный пункт заметен, но без яркой агрессии;
- на mobile используется поведение Quasar drawer;
- в свернутом режиме сохраняются иконки.

## Верхняя панель

Topbar содержит:

- кнопку меню;
- заголовок текущей страницы;
- подзаголовок рабочего места;
- глобальный поиск;
- состояние загрузки;
- профиль пользователя и выход.

Правила:

- topbar не должен занимать много вертикального места;
- поиск выглядит как поле, но открывает `GlobalSearch`;
- `Ctrl+K` / `Cmd+K` открывает глобальный поиск;
- `Ctrl+F` остается браузерным поиском.

## Dashboard-виджеты

Dashboard строится из виджетов:

- `StatsWidget`;
- `QuickActionsWidget`;
- `RecentActivityWidget`;
- `NotificationsWidget`;
- `TasksWidget`.

Правила:

- виджеты компактные;
- не помещать карточки в карточки;
- статистика отделяется от списков действий;
- mock-данные явно помечаются в коде;
- быстрые действия ведут в существующие разделы без скрытых side effects.

## Адаптивность

Breakpoints описаны в `docs/RESPONSIVE_WORKSPACE.md`.

Правила для рабочих ширин:

### 1366 px

- Dashboard: 2 колонки;
- страницы с широкой таблицей могут переходить в одну колонку;
- карточка переносится под таблицу, если таблица становится нечитаемой;
- sidebar видим, но можно использовать компактность.

### 1920 px

- Dashboard: 3 колонки;
- таблица + карточка обычно в две колонки;
- карточка `380-420px`;
- таблица занимает оставшееся место.

### 2560 px

- Dashboard: 4 колонки;
- рабочая область расширяется контролируемо;
- не растягивать длинные текстовые строки без необходимости;
- использовать ширину для большего количества данных.

### 3440 px

- сохранять ограниченную читаемую ширину секций;
- не растягивать карточки на всю ширину;
- Dashboard и рабочие доски могут использовать ultrawide-пространство для дополнительных колонок;
- таблицы должны оставаться сканируемыми.

## Lucide Icons

Lucide Icons — основной набор иконок.

Правила:

- использовать иконки из `@lucide/vue`;
- типовой размер в меню: `18-20px`;
- типовой размер в кнопках: `16-18px`;
- иконка должна помогать распознаванию действия;
- не использовать разные наборы иконок без причины;
- не рисовать вручную SVG, если есть подходящая Lucide-иконка;
- для специфического официального логотипа использовать брендовый файл, а не Lucide.

## Связь с UI Foundation

`docs/DESIGN_SYSTEM.md` задает визуальные правила верхнего уровня. `docs/UI_FOUNDATION.md` описывает реализацию через базовые компоненты `AppPage`, `AppTable`, `AppCard`, `AppFilterBar`, `AppStatusBadge` и другие.

Если возникает противоречие:

1. официальный бренд и логотип имеют приоритет;
2. затем `docs/DESIGN_SYSTEM.md`;
3. затем `docs/UI_FOUNDATION.md`;
4. затем локальные решения конкретной страницы.

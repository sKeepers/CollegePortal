# Электронное личное дело студента: что есть, что требуется, чего нет

**Разбор для решения владельца.** Составлен 23.08.2026 чатом «Контингент и
карточки студентов». Вопрос о составе электронного личного дела задан владельцу
19.08 и остался без ответа; ФРДО стоит на нём третий заход подряд.

Документ написан так, чтобы **к ответу владельца оставалось строить, а не
разбираться**: всё, что можно выяснить без него, выяснено и замерено.

**Главный вывод в одну строку:** портал уже умеет хранить электронное личное дело
целиком — виды аттестатов, разделы сканов, статусы проверки, версии документов.
Не хватает **не кода, а данных и одного решения**.

## Замер: сколько карточек готово к ФРДО прямо сейчас

| | |
| --- | --- |
| Студентов на стенде | 596 |
| Есть карточка человека | 593 |
| Есть документ, удостоверяющий личность | 573 |
| Есть СНИЛС | 572 |
| **Есть документ об образовании** | **0** |
| **Карточек, полных по правилам ФРДО** | **0** |
| Файлов (сканов) документов | 0 |
| Выпускников, дипломов | 0 и 0 |

**Ноль полных карточек из 596, и причина ровно одна — документ об образовании.**
Всё остальное уже собрано: паспорта легли 23.08 из выгрузок ФИС, СНИЛС тоже.

*Замечено попутно:* студентов стало 596 при 593 карточках человека — три записи
заведены не через загрузку контингента и остались без человека. Это чужая работа,
не трогал; но такие карточки в ФРДО не пройдут по первому же правилу.

## 1. Что портал уже хранит по студенту

Личное дело в портале разложено по четырём слоям. Слои существуют, поля заведены,
экраны есть.

### Карточка человека (`people`)

Общее, что не меняется от роли: ФИО, дата рождения, пол, гражданство, место
рождения, СНИЛС (открытым значением и хешем), ИНН, телефон, e-mail, адрес, фото.

### Учебная карточка (`students`)

Всё, что относится к обучению: группа, форма обучения и финансирования, статус,
дата зачисления, номер и дата приказа, **номер и буква личного дела**, реквизиты
паспорта зеркалом, адрес, телефон, дата архивации.

### Документ, удостоверяющий личность (`admission_identity_documents`)

Отдельная таблица у человека, с версиями. Серия, номер, хеш номера, дата выдачи,
кем выдан, **код подразделения**, вид документа из справочника, страна и место
выдачи, срок действия, признак основного, статус проверки, кто и когда проверил,
поля для ФИС.

Справочник видов знает пять: паспорт РФ, свидетельство о рождении, иностранный
документ, временное удостоверение, иной.

### Документ об образовании (`admission_education_documents`)

Та же машинерия, и она **шире, чем кажется**: серия, номер, хеш номера, дата
выдачи, **кем выдан — то самое «учебное заведение»**, страна, уровень образования,
**год окончания**, **средний балл и его шкала**, признак оригинала и дата его
получения, признак наличия приложения, регистрационный номер, квалификация,
специальность, признак нострификации, статус проверки, версии.

Справочник видов знает семь: аттестат об основном общем, аттестат о среднем
общем, диплом СПО, диплом НПО, иностранный документ, академическая справка, иной.

### Сканы (`admission_document_files`)

Файлы прикрепляются к документу с указанием раздела: **основной разворот,
приложение, регистрация, первая сторона, вторая сторона, другое**. То есть
«электронное дело как сканы» портал поддерживает уже сейчас — просто ни одного
файла не загружено.

### Выпуск и диплом (`graduates`, `diplomas`, `diploma_supplements`)

Выпускник, год выпуска, квалификация, программа, специальность; диплом с серией,
номером, регистрационным номером, датой выдачи и статусом; приложение к диплому.
Таблицы, модели, API и экраны есть. Записей — ноль.

## 2. Чего требует ФРДО

Список взят **из кода, а не из общих слов** — `FrdoPackageController::validateRecord`
и `AdmissionDocumentReadinessService`. Пакет с невыполненным условием объявляется
невалидным и не выгружается.

### По записи выпускника — десять проверок

ФИО выпускника · дата рождения · специальность · образовательная программа ·
серия диплома · номер диплома · регистрационный номер · дата выдачи диплома ·
квалификация · статус диплома.

### По карточке студента — четыре проверки

| Требуется | Есть на стенде |
| --- | --- |
| Карточка связана с человеком | 593 из 596 |
| Документ, удостоверяющий личность | 573 |
| **Документ об образовании** | **0** |
| СНИЛС | 572 |

**Именно четвёртый слой и держит ФРДО.** Первые три собраны, четвёртого нет ни у
кого.

## 3. Чего требует архивное личное дело

Портал хранит **реквизиты**, архив хранит **бумагу**. Электронное дело имеет смысл
ровно тогда, когда отвечает на вопрос «что лежит в папке и в каком виде».

Состав, который обычно образует дело студента СПО и который портал уже способен
удержать:

| Часть дела | Где в портале | Есть ли данные |
| --- | --- | --- |
| Заявление о приёме | `applicant_applications` | пусто |
| Документ об образовании (аттестат) с приложением | `admission_education_documents` + сканы | **пусто** |
| Документ, удостоверяющий личность | `admission_identity_documents` | 573 |
| СНИЛС | `people.snils` | 572 |
| Приказ о зачислении | `students.enrollment_order_*` | 593 |
| Фотография | `people.photo_path` | **0** |
| Приказы о движении (перевод, отчисление, восстановление) | **места нет** | — |
| Договор об обучении | **места нет** | — |
| Диплом и приложение при выпуске | `diplomas`, `diploma_supplements` | пусто |
| Опись дела | **места нет** | — |

**Четыре вопроса владельцу, без ответа на которые дело не построить.** Они заданы
19.08 и повторены здесь дословно:

1. **Что считается делом** — сканы документов, или ещё и реквизиты отдельными
   полями? От этого зависит, обязательны ли серия и номер, или достаточно скана.
2. **Кто открывает дело** — какие роли видят содержимое, какие только опись.
3. **Где лежат файлы и что попадает в резервную копию** — сканы в хранилище
   портала растут быстро, а копия снимается целиком.
4. **Сколько дело хранится после выпуска** — от этого зависит, что удалять и что
   переносить в архив.

К ним разбор добавляет пятый — технический, но такой же обязательный:

5. **Нужны ли приказы о движении, договор и опись** отдельными сущностями? Сейчас
   в портале места для них нет. Если дело должно быть полным по описи — это
   отдельная работа, и её объём зависит от ответа.

## 4. Чего нет ни в одном источнике

| Чего нет | У скольких | Где искать |
| --- | --- | --- |
| **Аттестат: серия, номер, дата выдачи** | у всех 596 | только личные дела на бумаге |
| Приложение к аттестату | у всех | только бумага |
| Сканы любых документов | у всех | не загружались ни разу |
| E-mail | у всех | нет ни в выгрузках ФИС, ни в списках |
| Место рождения | 595 из 596 | в выгрузках ФИС одно значение на 847 строк |
| Заявления о приёме | у всех | `applicant_applications` пуста |

**Название школы — особый случай.** Оно есть: 580 названий лежат в
`.local/Зачисление 2026-2027 - все студенты.csv`, колонка «Учебное заведение».
Место для него в портале тоже есть —
`admission_education_documents.document_organization`.

**Мешает одна строка кода.** `EducationDocumentService::syncForPerson` отказывается
создавать документ, если не заданы ни серия, ни номер:

```php
if (! isset($payload['series']) && ! isset($payload['number'])) {
    return null;
}
```

То есть школа не может лечь в портал **до тех пор, пока не появится аттестат**.
Это не дефект — это осознанная строгость: документ без реквизитов ничего не
удостоверяет. Но решение здесь принимает владелец, и оно бинарное:

- **либо** разрешить документ об образовании без серии и номера — тогда 580
  названий школ и годы окончания ложатся сегодня, а реквизиты дописываются
  позже, когда аттестаты соберут;
- **либо** ждать аттестаты и грузить документы целиком — тогда ФРДО стоит до тех
  пор.

## 5. Что приходит вместе с аттестатом

**Один ответ владельца закрывает и личное дело, и ФРДО.** Ниже — всё, что даёт
аттестат, если его собрать и внести:

| Что даёт аттестат | Куда ложится | Что этим закрывается |
| --- | --- | --- |
| Серия | `admission_education_documents.series` | **создание документа об образовании** — четвёртая проверка ФРДО |
| Номер | `.number` (+ хеш) | то же |
| Дата выдачи | `.issue_date` | то же |
| Кем выдан — школа | `.document_organization` | **580 названий, которым сейчас некуда лечь** |
| Год окончания | `.graduation_year` | опись дела, отчётность |
| Вид документа (основное/среднее общее) | `.document_type_id` | различение девятиклассников и одиннадцатиклассников |
| Средний балл документа | `.average_score` | конкурсные справки; в учебную карточку не переносится |
| Наличие приложения | `.has_attachment` | полнота дела |
| Скан разворота и приложения | `admission_document_files` | **электронное дело как сканы** |

**Итог: аттестат закрывает четвёртую проверку ФРДО у всех, кто его принесёт, и
одновременно даёт школу, год окончания и приложение.** Ничего из этого не требует
ни строчки кода — только данные и решение по пункту 4.

Чего аттестат **не** закрывает: e-mail, место рождения, заявления о приёме,
приказы о движении, договор и опись.

## 6. Что решать владельцу

Собрано в один список, чтобы ответить разом:

1. **Разрешить документ об образовании без серии и номера** — да или нет.
   От этого зависит, ложатся ли 580 школ сегодня или ждут аттестатов.
2. **Собираются ли аттестаты** — и если да, то в каком виде: реквизиты руками,
   сканы, или и то и другое.
3. **Четыре вопроса о составе дела** из раздела 3 — что считается делом, кто
   открывает, где файлы и что в копии, сколько хранится.
4. **Нужны ли приказы о движении, договор и опись** отдельными сущностями.

## 7. Выпуск и дипломы: что готово и что развалится

Проверено **сквозняком на копии стенда**, на настоящих данных: взята группа
набора 2023 целиком, заведены выпускники, выданы дипломы, собран пакет ФРДО и
запущена та же проверка, какой пользуется портал.

### Что готово

Модули выпуска и ФРДО существуют целиком: таблицы `graduates`, `diplomas`,
`diploma_supplements`, `frdo_packages`, `frdo_records`, `frdo_validation_errors`;
модели, одиннадцать маршрутов API, выгрузка и загрузка выпускников, экраны
«Выпуск» и «ФРДО». **Записей в них ноль** — ни одного выпускника, ни одного
диплома.

### Что работает на настоящих данных

**Цепочка группа → программа → специальность доходит у всех.** Замер: у всех 68
групп есть программа, у всех программ — специальность, у всех специальностей —
квалификация. Все 121 четверокурсник получают специальность и квалификацию
автоматически, руками вносить не надо.

Это стоило проверить: `GraduateController` выводит специальность и квалификацию из
группы, и если бы цепочка где-то рвалась, каждый такой выпускник ложился бы в
пакет невалидным.

### Что развалится

Сквозняк: 8 выпускников, дипломы выданы четверым. Пакет ФРДО — **`validation_failed`,
28 ошибок**:

| Ошибка | Записей |
| --- | --- |
| **`student_card.education_document` — нет документа об образовании** | **8 из 8** |
| `diploma_series`, `diploma_number`, `registration_number`, `issue_date`, `diploma_status` | по 4 |

**Главное: документ об образовании валит запись независимо от диплома.** Даже
безупречно выданный диплом не спасает — ошибка приходит от карточки студента.
Двадцать из двадцати восьми ошибок — это ожидаемое «диплома ещё нет» у четверых,
а восемь из восьми — тот самый четвёртый слой.

### Выпускной курс: чего не хватает поимённо

| | Четверокурсников |
| --- | --- |
| Всего (набор 2023) | 121 |
| **Без документа об образовании** | **121** |
| Без документа личности | 10 |
| Без СНИЛС | 10 |
| Без даты рождения | 1 |
| Без карточки человека | 0 |

Если аттестаты соберут только у выпускного курса — это 121 документ, и ФРДО
сдвинется. Остальные 475 карточек могут подождать: их выпуск не завтра.

### Замеченное попутно

**Выпускника можно завести с неполной карточкой** — на создании проверки нет,
она стоит только на проверке пакета ФРДО. Это скорее правильно: черновик
заводится заранее, полнота требуется в момент выгрузки. Но знать стоит: список
выпускников может выглядеть готовым, а пакет — рассыпаться.

## 8. Что можно делать, не дожидаясь ответа

- **Загрузить фотографии:** сейчас их ноль у всех 596. Место готово, к ФРДО это
  не относится, но дело без фотографии неполно.
- **Заполнить три карточки без человека** — те самые из замера: без человека
  документы прикрепить не к чему.
- **Собрать заявления о приёме** из выгрузок ФИС: `applicant_applications` пуста,
  а 847 строк с номерами заявлений и датами регистрации лежат в `.local`.
  Это отдельная работа и отдельное решение — нужна ли она вообще, если приёмная
  кампания 2026 уже закрыта.

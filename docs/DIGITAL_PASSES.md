# Digital Identity и QR-пропуска

Дата: 2026-07-01

Документ описывает QR-001: первый MVP цифровых пропусков CollegePortal на базе Identity Domain.

## Назначение

Модуль цифровых пропусков создает техническую цифровую идентичность для существующих студентов и преподавателей. В Phase 1 пропуск представлен как QR-код, который содержит только `token`.

Персональные данные в QR не записываются. ФИО, телефон, email и статус владельца доступны только через защищенный API после авторизации.

## Реализовано в QR-001

Backend:

- таблица `digital_identities`;
- модель `DigitalIdentity`;
- API выпуска, списка, отзыва и получения QR;
- SVG QR генерируется backend-сервисом;
- token создается как UUID;
- при выпуске нового активного пропуска старый активный/приостановленный пропуск этого владельца отзывается.

Frontend:

- раздел `/identity/digital-passes`;
- пункт меню `Identity / Цифровые пропуска`;
- список цифровых пропусков;
- карточка выбранного пропуска справа;
- QR-код;
- выпуск пропуска для студента или преподавателя;
- отзыв пропуска;
- быстрый переход к владельцу.

## Таблица digital_identities

Поля:

- `id`;
- `entity_type`: `student` или `teacher`;
- `entity_id`;
- `token`;
- `status`: `active`, `suspended`, `revoked`, `expired`;
- `issued_at`;
- `expires_at`, nullable;
- `revoked_at`, nullable;
- `created_at`;
- `updated_at`.

## API

### GET /api/digital-identities

Возвращает список цифровых пропусков.

Фильтры:

- `entity_type`;
- `status`.

### POST /api/digital-identities/issue

Выпускает новый пропуск.

Payload:

```json
{
  "entity_type": "student",
  "entity_id": 1,
  "expires_at": null
}
```

### POST /api/digital-identities/{id}/revoke

Отзывает пропуск.

### GET /api/digital-identities/{id}/qr

Возвращает SVG QR-код. QR содержит только token.

## Безопасность

- QR не содержит ФИО, телефон, email, группу, должность или другие персональные данные.
- QR содержит только случайный token/UUID.
- SVG QR отдается только через защищенный API.
- Для проходной следующий этап должен проверять token на backend и только затем показывать оператору разрешенные данные.
- Отозванный или просроченный token не должен давать доступ.

## Связь с Identity Domain

QR-001 пока использует `entity_type` и `entity_id`, чтобы не ломать существующие таблицы. В будущем эта таблица должна быть связана с `Person` и `Digital Identity` из `docs/IDENTITY_DOMAIN.md`.

Текущая модель является переходной:

- сейчас: `student` / `teacher`;
- следующий этап: `person_id` и роли Person;
- дальше: QR, Mobile QR, RFID/NFC, Face ID без изменения пользовательских сценариев.

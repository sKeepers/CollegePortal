# Демонстрационная база CollegePortal

Документ описывает синтетический набор данных для DEV-стенда CollegePortal. Набор предназначен для демонстрации руководству, преподавателям и приемной комиссии без предварительной ручной подготовки.

## Ограничения

- Использовать только в DEV/TEST окружениях.
- В production команды создания и очистки демонстрационной базы заблокированы.
- Демо-набор не содержит реальные ФИО, телефоны, email, СНИЛС, ИНН, паспортные данные или адреса.
- Все email используют домен `demo.college-portal.local`.
- Все технические коды и служебные признаки используют префикс `DEMO` или комментарий `[DEMO-002]`.

## Создание

Из каталога backend:

```bash
php artisan demo:seed --reset
```

Команда сначала удаляет предыдущий DEMO-набор, затем создает актуальную демонстрационную базу.

Через интерфейс администратора доступно то же действие:

`/admin/data-management` -> `Создать демо-данные`.

## Очистка

Из каталога backend:

```bash
php artisan demo:reset
```

Через интерфейс администратора:

`/admin/data-management` -> `Очистить демо-данные`.

Очистка удаляет только синтетические записи с DEMO-префиксами и доменом `demo.college-portal.local`. Рабочие данные вне DEMO-набора не затрагиваются.

## Состав DEMO-набора

Базовый объем:

- 600 студентов;
- 70 преподавателей;
- 30 учебных групп;
- специальности и образовательные программы;
- отделения и должности;
- аудитории;
- учебные планы и дисциплины;
- нагрузка преподавателей;
- расписание на учебную неделю;
- занятия электронного журнала;
- посещаемость и оценки;
- домашние задания и комментарии занятий;
- заявления приемной комиссии и документы;
- цифровые пропуска и последние события проходной;
- демонстрационные audit-события;
- демонстрационные уведомления мобильного кабинета.

## Баннер

После создания DEMO-набора включается публичная настройка:

- `demo.mode_enabled = true`;
- `demo.banner_text = Демонстрационный режим`.

Интерфейс показывает верхний баннер `Демонстрационный режим`, чтобы зрители понимали, что стенд не содержит реальных персональных данных.

После `demo:reset` настройка `demo.mode_enabled` переключается в `false`.

## Dashboard

DEMO-набор создает данные для основных агрегатов Dashboard:

- контингент;
- преподаватели;
- расписание на сегодня и неделю;
- журнал и посещаемость;
- приемная комиссия;
- проходная;
- audit-события.

Цель набора - убрать нулевые показатели на DEV-демонстрации и показать реалистичные сценарии без реальных данных.

## Проверка перед показом

1. Выполнить миграции DEV-БД.
2. Выполнить `php artisan demo:seed --reset`.
3. Собрать frontend.
4. Открыть `/dashboard` и проверить ненулевые показатели.
5. Открыть `/students`, `/teachers`, `/groups`, `/schedule`, `/journal`, `/admissions`, `/access/reports`.
6. Убедиться, что в интерфейсе виден баннер `Демонстрационный режим`.
7. Не использовать реальные учетные записи и реальные персональные данные во время показа.

## Поддержка

При добавлении нового модуля в DEMO-набор нужно:

1. Использовать только синтетические значения.
2. Добавить записи в `DemoDataSeeder` отдельным методом.
3. Добавить очистку этих записей в `clearDemo()`.
4. Добавить счетчик в `summary()`.
5. Обновить regression-тесты.
6. Обновить этот документ.

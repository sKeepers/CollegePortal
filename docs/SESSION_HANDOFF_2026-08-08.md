## Очередь

1. **Здания и «кто сейчас внутри».** Справочник точек прохода с привязкой к корпусу, живой поимённый список по каждому зданию, экран под телефон. Практика систем контроля доступа называет это muster report, главный сценарий — эвакуация, поэтому список должен открываться с телефона и не требовать фильтров. Начата первая миграция, ничего не отправлено.
2. **Массовая выдача карточек доступа.** Выбор группы в «Студентах», создание учётных записей разом, PDF с карточками на печать и CSV. Пароль показывается один раз и не восстанавливается — только сброс, и это надо написать на экране.
3. **Отчёты по проходам.** День, неделя, месяц; тип «Сотрудники» в фильтре; «только опоздавшие»; переход в карточку человека; информативный экспорт за период. Расчёты брать из существующего разбора посещаемости, а не дублировать: опоздания по расписанию там уже работают.
4. **Карточки людей.** Свести разные названия кнопки пропуска к одному и добавить создание и сброс учётной записи прямо в карточке.

## Ждут решения владельца

- Объединение дублей учётных записей с приставкой UAT: меняется логин, текущая сессия прерывается, нужен удобный момент.
- Справки и зачётные книжки для «Учебной части 2»: в портале их нет — ни модуля, ни прав, ни экранов. Это разработка, а не настройка роли.
- `SEC-002` — перенос токена из браузерного хранилища. Блокирует `AUTH-005`, а через него вход через Telegram и MAX, и остаётся стоп-фактором перед загрузкой реальных персональных данных.
- ФИС ГИА: доступ к тестовому контуру не проверен, `SoapFisTransport` остаётся заглушкой.
- SMTP для восстановления пароля: отправка через `smtp.mail.ru` с ящика `portal@skki.ru`, иначе не пройдёт SPF.

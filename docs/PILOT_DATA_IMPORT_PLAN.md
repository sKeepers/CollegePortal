# PILOT_DATA_IMPORT_PLAN: план пилотной загрузки реальных данных

Дата: 08.07.2026.  
Окружение: DEV `/srv/college-dev`.  
PROD: не используется и не изменяется.

## Цель

Подготовить первую загрузку реальных данных колледжа через `/admin/import` и связанные административные разделы CollegePortal. Документ фиксирует порядок загрузки, входные файлы, контроль качества и риски до начала работы с персональными данными.

На этапе DATA-001 код приложения, backend, frontend, база данных и API не менялись. Подготовлены только документы, описания шаблонов и инструкции.

## Текущий статус импорта

В Release 0.7 универсальный импорт `/admin/import` уже поддерживает:

- студенты;
- группы;
- преподаватели;
- дисциплины;
- аудитории;
- абитуриенты.

Для учебных планов, нагрузки и расписания подготовлены описания шаблонов, но их загрузка через `/admin/import` требует отдельного расширения backend/frontend. Эти файлы можно использовать для сбора и нормализации данных до реализации импорта.

## Общий порядок пилотной загрузки

1. Справочники.
2. Специальности.
3. Образовательные программы.
4. Группы.
5. Преподаватели.
6. Дисциплины.
7. Аудитории.
8. Студенты.
9. Учебные планы.
10. Нагрузка.
11. Расписание.
12. Абитуриенты.

## Почему порядок именно такой

- Справочники нужны до загрузки основных данных, чтобы статусы, формы обучения и виды документов не расходились между модулями.
- Специальности и образовательные программы должны существовать до групп, студентов и абитуриентов.
- Группы загружаются до студентов, чтобы студент сразу связывался с корректной группой.
- Преподаватели, дисциплины и аудитории нужны до расписания, журнала и нагрузки.
- Учебные планы и нагрузка лучше загружать после базовых учебных сущностей.
- Расписание зависит от групп, преподавателей, дисциплин и аудиторий.
- Абитуриенты можно грузить отдельно, но для приемной комиссии желательно заранее сверить образовательные программы.

## Этап 1. Справочники

Раздел: `/admin/reference`.

Что проверить перед импортом:

- формы обучения;
- формы финансирования;
- статусы студентов;
- статусы заявлений абитуриентов;
- виды занятий;
- виды учебной нагрузки;
- виды экзаменов;
- статусы дипломов;
- типы документов.

Правило: если в Excel используются значения, которых нет в справочниках, сначала добавить или согласовать эти значения, затем выполнять импорт.

## Этап 2. Специальности

На текущем этапе специальности могут быть частью данных групп, образовательных программ и выпускников. Перед массовым импортом нужно подготовить единый список специальностей:

- код специальности;
- наименование;
- квалификация;
- срок обучения;
- форма обучения;
- статус.

Если отдельного импорта специальностей нет в текущем интерфейсе, список используется как контрольный справочник для сверки значений в шаблонах групп, программ и студентов.

## Этап 3. Образовательные программы

Нужно подготовить список программ:

- наименование программы;
- специальность;
- форма обучения;
- год начала действия;
- статус;
- квалификация.

Программы используются группами, абитуриентами, учебными планами и выпускниками.

## Правила выполнения пилотного импорта

1. Загружать данные сначала небольшими пакетами: 10-30 строк для каждого типа.
2. Использовать режим `Создать новые записи` только для первичной загрузки.
3. Для повторной загрузки использовать `Обновить существующие по ключу` или `Пропустить дубли` после проверки ключа.
4. После каждого импорта смотреть отчет и историю `/admin/import`.
5. Ошибки исправлять в исходном Excel/CSV, а не напрямую в базе.
6. После загрузки каждого типа выполнять выборочную сверку карточек в соответствующем разделе.
7. Все спорные значения справочников фиксировать отдельно до массовой загрузки.

## Контроль после загрузки

После каждого этапа проверить:

- количество созданных, обновленных, пропущенных и ошибочных строк;
- наличие ошибок с номером строки и колонкой;
- карточки 3-5 случайных записей;
- связи между сущностями: студент -> группа, группа -> студенты, преподаватель -> расписание;
- audit log `/admin/audit`;
- отсутствие случайных дублей.

## Критерии готовности к массовой загрузке

- Справочники согласованы.
- Шаблоны заполнены без пустых обязательных полей.
- Даты приведены к единому формату `ДД.ММ.ГГГГ` или ISO `YYYY-MM-DD`.
- ФИО разделены на фамилию, имя и отчество.
- Группы и программы написаны одинаково во всех файлах.
- Определены ключи обновления для каждого типа данных.
- Пилотная загрузка малых файлов прошла без критических ошибок.

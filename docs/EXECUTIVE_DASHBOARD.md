# Executive Dashboard CollegePortal

## Назначение

Executive Dashboard — аналитическая главная страница для руководства колледжа. Она собирает агрегированные показатели из уже существующих модулей CollegePortal и показывает состояние колледжа без перехода по отдельным разделам.

Dashboard предназначен для ролей `admin` и `director`. Преподаватели и остальные роли используют свои рабочие столы или общий fallback Dashboard.

## Источники данных

Backend использует `DashboardAnalyticsService`. Сервис не меняет бизнес-логику и не записывает данные, а только читает существующие сущности:

- `Student` — контингент, активные студенты, студенты без фото;
- `Graduate` — выпускники;
- `ApplicantApplication` — абитуриенты, новые заявления, заявления без документов;
- `Teacher` — количество преподавателей;
- `TeachingLoadItem` — агрегированная нагрузка;
- `ScheduleLesson` — занятия сегодня и динамика занятий;
- `Exam` — экзамены сегодня;
- `Classroom` — свободные аудитории на текущий день;
- `AccessEvent` — входы, выходы, отказы, люди в здании;
- `FrdoPackage` и `FisPackage` — пакеты интеграций и ошибки проверки;
- `AuditLog` — последние события аудита;
- `frontend/public/version.json` — версия и build-информация.

API endpoint:

```text
GET /api/dashboard/analytics/executive
```

Endpoint находится под `api.token` и требует permission `view_reports`.

## KPI

### Контингент

- всего студентов;
- активных студентов;
- выпускников;
- абитуриентов.

### Преподаватели

- всего преподавателей;
- агрегированная нагрузка;
- отсутствуют сегодня, пока зарезервировано как показатель для будущей связки с проходной.

### Учебный процесс

- занятий сегодня;
- экзаменов сегодня;
- свободных аудиторий.

### Проходная

- людей сейчас в колледже;
- входов сегодня;
- выходов сегодня;
- отказанных проходов.

### Приемная комиссия

- новые заявления;
- ожидают проверки;
- зачислено.

### Интеграции

- ФРДО: готовые пакеты, ошибки, последние пакеты;
- ФИС: пакеты приема, пакеты ГИА, ошибки.

### Система

- версия;
- релиз;
- build hash;
- дата сборки;
- окружение;
- статус системы;
- последние события аудита.

## Мини-графики

Мини-графики строятся без сторонних библиотек. Сейчас используются простые bar chart элементы на CSS для последних 7 дней:

- заявления;
- входы через проходную;
- занятия.

Если в будущем данных будет недостаточно, допускается DEV/mock-ряд с явной пометкой `DEV`, но продуктивные данные не должны смешиваться с демо без визуального признака.

## Что требует внимания

Блок показывает показатели, которые требуют управленческой проверки:

- студенты без фото;
- заявления без подтвержденных документов;
- ошибки ФРДО;
- ошибки ФИС.

Каждый пункт ведет в профильный раздел, чтобы руководитель мог быстро перейти от агрегата к рабочим данным.

## Быстрые действия

Dashboard содержит быстрые переходы:

- Студенты;
- Приемная комиссия;
- Расписание;
- Проходная;
- Импорт;
- ФРДО;
- ФИС;
- Аудит.

## Как добавлять новые виджеты

1. Добавить расчет в `DashboardAnalyticsService` без записи в БД.
2. Вернуть данные в едином payload `data.kpi`, `data.charts`, `data.attention` или отдельном логическом блоке.
3. На frontend добавить виджет в `AdminDashboard.vue` или вынести новый компонент в `frontend/src/pages/dashboard/widgets/`.
4. Использовать существующие компоненты Design System: `AppCard`, `StatsWidget`, `QuickActionsWidget`, `RecentActivityWidget`, `AppStatusBadge`.
5. Не подключать тяжелые chart-библиотеки без отдельного архитектурного решения.

## Ограничения MVP

- “Отсутствуют сегодня” пока не считается полноценно, потому что отсутствия требуют правил рабочего дня и связки Person/Teacher с проходной.
- Мини-графики пока показывают 7 дней, не 30. Расширение до 30 дней должно быть сделано после проверки производительности и UX.
- Конфликты расписания в блоке внимания пока не отображаются отдельным показателем.
- Dashboard является read-only и не должен запускать действия изменения данных напрямую.

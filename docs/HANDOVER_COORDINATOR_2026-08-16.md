## Три вещи, которые дорого узнать заново

1. **Владелец читает код в локальной копии, а не на серверах.** Ссылка на файл, которого там нет, для него бесполезна. После каждого коммита: `git fetch dev && git merge --ff-only dev/develop`.
2. **Чаты оставляют работу незакоммиченной прямо в локальной копии владельца.** Случилось дважды: сначала `ARCH-001` (документы и `.gitattributes`), потом `MOB-002` (1400 строк). **Смотреть `git status` целиком, а не первые строки** — именно из-за обрезанного вывода второй случай чуть не пропустили.
3. **Файлы с рабочей станции приезжают с CRLF.** Перед коммитом на DEV снимать возврат каретки, иначе git покажет весь файл переписанным. На этом уже спотыкались: три документа показали 2000 изменённых строк вместо тридцати.

## Чего делать не следует

**Не править `ASSIGNMENTS.md` и `ACTIVE_WORK.md` перезаписью файла целиком.** Их одновременно правят несколько чатов, и перезапись сносит чужое. Этот чат столкнулся с тем, что файл ушёл из-под рук на середине правки.

**Не переключать ветки в локальной копии владельца, пока в ней работает чат.** Один раз пришлось: копию сняли с `develop` ради спасения файлов, и вернуть её сразу было нельзя — сверху лежала незавершённая работа.

**Координирующий чат должен быть один.** Их было двое, и оба правили одни и те же файлы. Перед началом работы убедиться, что второго нет.

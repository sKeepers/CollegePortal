# Mobile Access Scanner

## Назначение

Мобильный сканер проходной позволяет сотруднику проходной или администратору считывать QR-пропуска камерой телефона и отправлять результат в существующий endpoint:

```text
POST /api/access/scan
```

Логика проходной не дублируется: направление вход/выход, проверка активного/отозванного/неизвестного пропуска и защита от повторного скана остаются в существующем backend/API.

## Доступ

Frontend route:

```text
/access/mobile-scanner
```

Доступен только ролям:

- `admin`;
- `security`.

Teacher/student и остальные роли перенаправляются на Dashboard frontend-guard. Backend endpoint `/api/access/scan` по-прежнему защищен permission middleware; в текущей модели `security` получает доступ через `manage_dictionaries`, teacher/student доступа не имеют.

## Механизм распознавания

Основной механизм:

- Native `BarcodeDetector`, если браузер поддерживает QR-коды.

Fallback:

- `jsQR` локально в браузере через `canvas`.

Кадры камеры не отправляются на сервер и не сохраняются. На сервер отправляется только считанная строка QR.

## Требования HTTPS

Для доступа к камере браузер требует secure context:

- HTTPS;
- или `localhost` для локальной разработки.

На телефоне открывать DEV/PROD нужно по HTTPS через reverse proxy или доверенный туннель. По обычному `http://IP` большинство мобильных браузеров камеру заблокируют.

Для DEV использовать:

```text
https://192.168.34.114:5443/access/mobile-scanner
```

Не использовать `https://192.168.34.114:5174`: порт `5174` является HTTP-only и даст `ERR_SSL_PROTOCOL_ERROR` до загрузки приложения.

## Поддерживаемые браузеры

Рекомендуется:

- Chrome / Chromium на Android;
- Edge на Android;
- Safari iOS 16+ с HTTPS.

`BarcodeDetector` поддерживается не везде, поэтому включен fallback `jsQR`.

## Возможности интерфейса

- запрос разрешения камеры;
- выбор задней камеры по умолчанию;
- переключение камеры;
- включение фонарика, если браузер и устройство поддерживают `torch`;
- непрерывное распознавание QR;
- отправка считанного значения в `/api/access/scan`;
- крупный результат: Разрешено / Отказано;
- ФИО владельца, тип, вход/выход, время, причина отказа;
- вибрация: короткая при allowed, двойная при denied;
- звуковой сигнал;
- автоматическая пауза после успешного чтения;
- кнопка `Сканировать снова`;
- ручной ввод token или `CP1:<token>`.
- ручной ввод короткоживущего `CP2:<expires>:<signature>`.

## CP2 QR

Страница студента `/m/student/pass` показывает CP2 QR, который обновляется каждые 30 секунд.

Сканер передает считанную строку в существующий endpoint:

```text
POST /api/access/scan
```

Backend сам определяет тип payload:

- `CP2:<expires>:<signature>` — короткоживущий мобильный QR;
- `CP1:<token>` — legacy compatibility;
- `<token>` — административный технический token цифрового пропуска.

CP2 не содержит персональные данные, постоянный token пропуска или простой последовательный ID. Просроченный CP2 не связывается с владельцем и возвращает отказ.

## Ограничения MVP

- Распознавание зависит от качества камеры и освещения.
- Фонарик доступен не во всех браузерах.
- На iOS поддержка `torch` может отсутствовать.
- Если камера недоступна, нужно использовать USB HID-сканер на `/access/gate` или ручной ввод на странице мобильного сканера.
- В QR по-прежнему не должно быть персональных данных.

## Порядок использования

1. Открыть `/access/mobile-scanner` на телефоне.
2. Войти под пользователем с ролью `admin` или `security`.
3. Нажать `Запустить камеру`.
4. Разрешить доступ к камере.
5. Навести рамку на QR-пропуск.
6. Проверить результат прохода.
7. Нажать `Сканировать снова` для следующего человека.

## Fallback

Если камера не работает:

1. Использовать ручной ввод на `/access/mobile-scanner`.
2. Использовать USB HID-сканер на `/access/gate`.
3. Проверить физический сканер через `/access/scanner-test`.

# Schedule Visual Editor

## Назначение

Visual Schedule Editor — рабочий слой поверх Schedule Engine для учебной части. Он позволяет создавать, переносить и применять шаблоны занятий через недельную сетку, не обходя preview/validation/apply.

## Режимы `/schedule`

Сохранены существующие режимы:

- День;
- Неделя;
- Преподаватель;
- Группа;
- Аудитория;
- Конфликты;
- Покрытие нагрузки.

Добавлены:

- Редактор недели;
- Шаблоны.

## Недельная сетка

Редактор недели строится как таблица:

- колонки: дни выбранной календарной недели;
- строки: номера пар;
- ячейка: одно или несколько занятий;
- данные загружаются по `date_from` / `date_to`, а не за весь учебный год.

На 1366 px сетка имеет внутренний горизонтальный scroll. Правая панель деталей не перекрывает расписание.

## Карточка занятия

Карточка в ячейке показывает:

- дисциплину;
- группу;
- преподавателя;
- аудиторию;
- время.

Состояния:

- обычное занятие;
- замена / перенос;
- отменено;
- конфликт.

Цвета используются из существующей спокойной палитры Design System.

## Создание занятия

Создание возможно:

- кнопкой «Создать занятие»;
- кликом по пустой ячейке редактора.

Перед сохранением вызывается `POST /api/schedule/preview`. Только после подтверждения выполняется `POST /api/schedule/apply`.

## Drag & Drop

Drag & drop разрешает перенос engine-занятия в другую ячейку недели.

Порядок:

1. пользователь перетаскивает карточку;
2. drop не сохраняет данные;
3. frontend вызывает preview через Schedule Engine;
4. пользователь видит blocking/warning;
5. apply вызывает endpoint move;
6. Audit фиксирует перенос.

Legacy-занятия без `schedule_entry_id` не переносятся drag & drop, чтобы не обходить Schedule Engine.

## Resize

Изменение длительности через resize не реализовано в ST-002B. Время можно изменить через перенос/редактирование, проходя validation/apply. Resize оставлен на следующий этап.

## Шаблоны

MVP поддерживает:

- список шаблонов;
- создание шаблона с одной строкой;
- тип недели: каждая / четная / нечетная;
- период действия;
- preview применения к выбранной неделе;
- apply на выбранную неделю.

Таблицы:

- `schedule_templates`;
- `schedule_template_entries`.

Расширенное редактирование множества строк шаблона и массовое применение на длинный период остается следующим этапом.

## Конфликты и покрытие

В редакторе доступны панели:

- Конфликты: blocking и warning;
- Покрытие нагрузки: planned/scheduled/remaining/over.

При создании занятия preview показывает конфликты до apply.

## RBAC

Используются permissions:

- `schedule.view`;
- `schedule.create`;
- `schedule.update`;
- `schedule.delete`;
- `schedule.validate`;
- `schedule.manage_templates`;
- `schedule.manage_replacements`;
- `schedule.view_conflicts`;
- `schedule.view_coverage`.

Поведение:

- director: read-only + конфликты/покрытие;
- deputy/study/academic_office: редактор;
- teacher: read-only;
- student: read-only;
- admin: все.

## Ограничения ST-002B

- frontend unit test runner не добавлялся; критичная логика покрыта backend/integration тестами Schedule Engine;
- resize не реализован;
- массовое удаление/очистка шаблонных записей не реализовано;
- сложный автогенератор расписания не реализован.

# Reference Data Platform

## Назначение

Reference Data Platform хранит нормативно-справочную информацию CollegePortal в единой структуре. Модуль нужен, чтобы формы обучения, статусы, виды занятий, типы документов и другие повторно используемые значения не были зашиты в отдельных компонентах, сидерах или конфигурационных файлах.

## Архитектура

Backend использует две таблицы:

- `reference_catalogs` - справочники;
- `reference_items` - элементы справочников.

`reference_catalogs` содержит:

- `code` - уникальный машинный код справочника;
- `name` - русское название;
- `description` - описание;
- `is_system` - системный справочник нельзя удалить.

`reference_items` содержит:

- `catalog_id` - связь со справочником;
- `code` - машинный код элемента внутри справочника;
- `name` - русское название;
- `sort_order` - порядок вывода;
- `is_active` - можно временно скрыть значение без удаления;
- `metadata` - дополнительные данные в JSON.

Системность элемента хранится в `metadata.is_system=true`, потому что отдельного поля `is_system` в структуре `reference_items` нет. Такие элементы нельзя удалить, но можно деактивировать.

## API

Административные endpoints:

- `GET /api/admin/reference/catalogs`
- `POST /api/admin/reference/catalogs`
- `PUT /api/admin/reference/catalogs/{id}`
- `DELETE /api/admin/reference/catalogs/{id}`
- `GET /api/admin/reference/items`
- `POST /api/admin/reference/items`
- `PUT /api/admin/reference/items/{id}`
- `DELETE /api/admin/reference/items/{id}`

Доступ выполняется через право `manage_dictionaries`.

## Системные справочники

Seeder `ReferenceDataSeeder` создает стартовые системные справочники:

- Формы обучения;
- Формы финансирования;
- Виды занятий;
- Виды учебной нагрузки;
- Статусы студентов;
- Причины отчисления;
- Причины академического отпуска;
- Типы документов;
- Виды экзаменов;
- Статусы дипломов;
- Статусы заявлений абитуриентов.

Seeder подключен к `DatabaseSeeder`, поэтому базовые справочники создаются вместе с общими данными DEV/UAT.

## Frontend

Раздел находится по маршруту `/admin/reference` и в меню `Система -> Справочники`.

Интерфейс позволяет:

- просматривать список справочников;
- выбирать справочник и видеть его элементы;
- создавать и редактировать пользовательские справочники;
- создавать и редактировать элементы;
- активировать и деактивировать элементы;
- удалять только пользовательские справочники и пользовательские элементы.

## Как добавлять новые справочники

Для пользовательского справочника достаточно создать запись через `/admin/reference`:

1. Указать код латиницей, например `performance_levels`.
2. Указать русское название.
3. Добавить элементы с кодами и русскими названиями.
4. Использовать `is_active=false` вместо удаления, если значение уже могло использоваться в данных.

Для системного справочника нужно добавить его в `ReferenceDataSeeder`, чтобы он воспроизводился на новых окружениях.

## Как подключать справочник к модулю

Рекомендуемый порядок:

1. В backend добавить ссылку на `reference_items.id` или хранить стабильный `code`, если миграция данных пока преждевременна.
2. В API отдавать список элементов по `catalog_code`.
3. На frontend использовать `GET /api/admin/reference/items?catalog_code=<code>&is_active=1`.
4. В формах показывать `name`, а сохранять `id` или `code` по решению конкретного модуля.
5. При удалении значений использовать деактивацию, чтобы не ломать исторические данные.

## Ограничения MVP

- Справочники пока административные, без отдельного публичного endpoint.
- Нет версионирования значений справочников.
- Нет массового импорта справочников.
- Нет автоматической миграции существующих hardcoded-статусов на reference items.


## CORE-004B: подключенные модули

На этапе CORE-004B справочники начали использоваться в существующих модулях без изменения бизнес-логики и структуры предметных таблиц.

Подключено:

- `Students` - статус студента из `student_statuses`;
- `Admissions` - статус заявления из `applicant_application_statuses`;
- `Exams` - вид экзамена из `exam_types`;
- `Teaching Load` - вид учебной нагрузки из `teaching_load_types`;
- `Graduation` - статус диплома из `diploma_statuses`.

Не менялось намеренно:

- существующие значения в БД;
- backend validation существующих модулей;
- CSV-форматы импорта/экспорта;
- локальные статусы, для которых системный справочник еще не утвержден отдельной задачей.

## ReferenceService и кэширование

Backend-сервис `ReferenceService` предоставляет единый доступ к справочникам:

```php
ReferenceService::catalog('education_forms');
ReferenceService::options('exam_types');
```

Справочники кэшируются на 30 минут. Кэш каталога сбрасывается при создании, редактировании или удалении справочника/элемента через административный API.

Frontend использует store `referenceOptions`, который загружает элементы через API `GET /api/admin/reference/items?catalog_code=<code>&is_active=1` и переиспользует их на странице.

## ADM-DOCS-001: applicant_document_types

Добавлен системный каталог `applicant_document_types` для документов абитуриента. Registry комплектности Admissions использует именно этот справочник, поэтому количество обязательных документов больше не задается константой UI или `documents_provided`.

Стартовые элементы: `passport`, `snils`, `education_document`, `photo`, `medical_certificate`, `personal_data_consent`. Metadata содержит обязательность, допустимые расширения и максимальный размер файла.

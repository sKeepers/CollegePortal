# Инструкция оператора проходной

## HID-сканер

1. Открыть `/access/checkpoint` или `/access/gate`.
2. Убедиться, что фокус находится в поле сканирования.
3. Отсканировать QR. Сканер должен передавать Enter в конце строки.
4. Дождаться результата: «Разрешено» или «Отказано».
5. При отказе использовать отображенную причину и не перепечатывать данные вручную без основания.

## Мобильный сканер

1. Открыть `/access/mobile-scanner` по HTTPS или в другом secure context.
2. Разрешить доступ к камере.
3. Использовать заднюю камеру, если она доступна.
4. После успешного скана страница ставит паузу, чтобы не считать QR повторно.
5. Нажать «Сканировать снова» для следующего человека.

## Ручной fallback

Ручной ввод доступен только пользователям с `access.override`. Для исправления события используется API override с обязательной причиной. Ручной режим не должен заменять штатное сканирование.

## Что видит оператор

Оператор получает только минимум: результат, имя для сверки, категорию владельца, фото при наличии и разрешении, группу или подразделение кратко, направление, время и причину отказа.

## ACCESS-002 smoke перед пилотом

Перед снятием draft-статуса PR #23 операторский сценарий должен быть проверен по чеклистам:

- `docs/ACCESS_CONTROL_MOBILE_TEST.md` — мобильный QR и камера телефона;
- `docs/ACCESS_CONTROL_HARDWARE_TEST.md` — реальный HID 2D-сканер;
- `docs/ACCESS_CONTROL_RELEASE_CHECKLIST.md` — merge readiness;
- `docs/ACCESS_CONTROL_LEGACY_DEPRECATION.md` — временная совместимость CP1/plain token.

Если мобильная камера не открывается из-за HTTP или недоверенного сертификата, тест останавливается до настройки DEV HTTPS. Небезопасные browser flags и отключение security checks не использовать.

Если HID-сканер не отправляет Enter suffix или теряет символы CP2 token, нужно зафиксировать модель и подготовить инструкцию настройки сканера. Глобально ослаблять parser запрещено.
## Известные проверки после ACCESS-002.4

Если повторно сканируется уже использованный CP2 QR, оператор должен видеть отказ с причиной replay, но карточка должна оставаться привязанной к известному синтетическому владельцу и его категории.

Если сканер работает при русской раскладке клавиатуры и выводит кириллические символы вместо `CP2:...`, система пытается восстановить значение только для строгого CP2-формата. При любом другом тексте оператор должен остановить тест и переключить раскладку на английскую, а не вводить токен вручную без основания.

DEV-аккаунты вида `*@local` допустимы для тестовой среды. Они не должны использоваться как реальные корпоративные адреса и не должны переноситься в PROD.

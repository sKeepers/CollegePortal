# Dashboard CollegePortal

## Назначение

Dashboard — главная рабочая страница после входа в CollegePortal. Он должен давать сотруднику быстрый обзор состояния колледжа и короткие пути к основным действиям без перехода в legacy-интерфейс.

Основные задачи Dashboard:

- показать ключевую статистику;
- дать быстрый доступ к частым действиям;
- показать последние события;
- показать уведомления;
- показать личные или ролевые задачи;
- стать основой для будущих рабочих столов по ролям.

## Структура виджетов

Базовая структура GUI-007:

- `StatsWidget` — ключевые показатели: студенты, группы, преподаватели, занятия сегодня;
- `QuickActionsWidget` — быстрые действия: добавить студента, добавить группу, открыть расписание, открыть журнал;
- `RecentActivityWidget` — последние действия в системе;
- `NotificationsWidget` — последние уведомления;
- `TasksWidget` — мои задачи.

Виджеты располагаются в responsive-grid:

- верхний блок — приветствие и дата;
- статистика — во всю ширину;
- быстрые действия и задачи — рядом на desktop;
- активность и уведомления — ниже, в две колонки на desktop и в одну колонку на узких экранах.

## Источники данных

На этапе GUI-007 backend и API не меняются.

Используем существующие API:

- `/students` — количество студентов;
- `/groups` — количество групп;
- `/teachers?active_only=1` — количество активных преподавателей;
- `/schedule-lessons` или доступный endpoint расписания — занятия сегодня, если endpoint уже поддерживает фильтры.

Если данных нет в существующих API, используются mock-данные. Mock-данные должны быть явно отделены в коде и легко заменяться на реальные API.

## Добавление новых виджетов

Чтобы добавить новый виджет:

1. Создать компонент в `frontend/src/pages/dashboard/widgets/`.
2. Передавать данные через props.
3. Не выполнять сложную бизнес-логику внутри виджета.
4. Загрузку данных держать на уровне `DashboardPage.vue` или будущего dashboard-store.
5. Для повторяемого визуала использовать UI Foundation-компоненты.
6. Если виджет временно использует mock-данные, явно назвать массив или объект с префиксом `mock`.

## Dashboard по ролям

В будущем Dashboard должен настраиваться по роли пользователя.

### Администратор

- состояние пользователей и справочников;
- интеграции;
- ошибки обменов;
- быстрый переход к системным настройкам;
- контроль задач обслуживания.

### Учебная часть

- расписание на день;
- группы без расписания;
- движение контингента;
- задачи по документам;
- отчеты по посещаемости и успеваемости.

### Преподаватель

- занятия сегодня;
- группы преподавателя;
- журнал к заполнению;
- отсутствующие оценки;
- уведомления по заменам.

### Приемная комиссия

- новые заявления;
- заявления с неполными документами;
- готовность к зачислению;
- конкурсные группы;
- быстрый переход к абитуриентам.

### Студент

- расписание на сегодня;
- оценки;
- посещаемость;
- уведомления;
- документы и справки.

## Правила реализации

- Dashboard не должен быть landing page.
- Интерфейс должен быть рабочим, плотным и похожим на внутреннюю систему.
- Не использовать декоративные hero-блоки.
- Все тексты интерфейса — на русском.
- Виджеты не должны ломать существующие API и legacy-доступ.
- Новые роли и персонализация добавляются после стабилизации базового Dashboard.

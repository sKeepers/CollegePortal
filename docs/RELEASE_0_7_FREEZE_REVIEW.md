# RELEASE-007: Freeze Review перед пилотной загрузкой данных

Дата фиксации: 08.07.2026  
Окружение проверки: DEV (`/srv/college-dev`)  
PROD: не изменялся

## Цель freeze review

Release 0.7 фиксирует текущее состояние CollegePortal Platform перед первой пилотной загрузкой реальных данных колледжа. На этом этапе код, backend, frontend, БД и API не менялись: выполнены только проверки, анализ и обновление документации.

Главная задача релиза: убедиться, что DEV-контур готов принять реальные данные через универсальный импорт, а команда понимает ограничения MVP и риски перед загрузкой.

## Готовность к пилотной эксплуатации

### Готово для пилотной загрузки в DEV

- Универсальный импорт поддерживает preview, mapping, validation, confirm и историю импортов.
- Есть шаблоны и подсказки по обязательным полям.
- Справочники вынесены в Reference Data Platform.
- Пользователи, роли, аудит и настройки колледжа готовы для административной проверки.
- Основные рабочие разделы открываются и проходят frontend build.
- Backend test suite проходит полностью.

### Требует пользовательской проверки

- Корректность реальных шаблонов данных колледжа.
- Соответствие статусов, форм обучения, форм финансирования и видов документов реальным справочникам колледжа.
- Сопоставление групп, специальностей, программ и дисциплин из реальных Excel/CSV.
- Дубликаты студентов, преподавателей и абитуриентов при обновлении существующих данных.
- Удобство рабочего процесса приемной комиссии, учебной части и администратора.

## Известные ограничения Release 0.7

- ФРДО и ФИС работают как подготовка, проверка и выгрузка данных, без реальной отправки во внешние системы.
- Moodle, LDAP/AD, Telegram/email-уведомления пока не интегрированы.
- Mobile Student Cabinet остается MVP.
- QR-проходная остается MVP и требует проверки на реальном USB HID-сканере.
- Распознавание лиц, NFC/RFID и offline mode не реализованы.
- Полноценный RBAC еще не завершен: роли и пользователи есть, но детальные permissions требуют следующего этапа.
- Frontend требует будущей оптимизации chunk size.
- Реальные производственные объемы данных еще не проверены нагрузочно.

## Риски перед загрузкой реальных данных

1. Качество исходных Excel/CSV.
   - Возможны разные форматы дат, телефонов, ФИО и названий групп.
   - Нужна предварительная чистка или настройка mapping.

2. Дубли и ключи обновления.
   - Нужно заранее определить ключи для студентов, преподавателей, групп и абитуриентов.
   - Email/телефон не всегда надежны как уникальный ключ.

3. Справочники.
   - Реальные значения могут отличаться от стартовых системных справочников.
   - Перед импортом нужно согласовать справочники: формы обучения, статусы, виды документов, формы финансирования.

4. Персональные данные.
   - Реальная загрузка должна выполняться только в согласованном окружении.
   - Нужен контроль доступа, аудит действий и аккуратное обращение с экспортами.

5. PROD-deploy.
   - Release 0.7 проверен в DEV.
   - PROD переносить только после backup, отдельного подтверждения и deployment checklist.

6. Связанные данные.
   - При импорте групп, студентов, программ и дисциплин важен правильный порядок загрузки.
   - Ошибки связей могут проявиться в расписании, журнале, нагрузке и отчетах.

## Рекомендованный порядок пилотной загрузки

1. Согласовать справочники в `/admin/reference`.
2. Проверить настройки колледжа в `/admin/settings`.
3. Загрузить группы.
4. Загрузить специальности/программы, если они входят в текущий набор данных.
5. Загрузить дисциплины.
6. Загрузить преподавателей.
7. Загрузить аудитории.
8. Загрузить студентов.
9. Загрузить абитуриентов, если проверяется приемная комиссия.
10. Проверить отчеты импорта и audit log.
11. Провести выборочную сверку карточек студентов, групп, преподавателей и абитуриентов.

## Итоговый вывод

CollegePortal Release 0.7 в DEV готов к пилотной загрузке реальных данных при условии, что загрузка будет выполняться сначала в DEV, по согласованным шаблонам, с предварительной проверкой справочников и последующей выборочной сверкой данных пользователями колледжа.

Перенос в PROD на этом этапе не выполнялся и должен рассматриваться отдельной задачей после успешной пилотной загрузки и UAT.

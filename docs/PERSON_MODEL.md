# Person Model CollegePortal

## Назначение

`Person` - центральная сущность физического лица в CollegePortal. Она нужна, чтобы постепенно объединить студентов, преподавателей, абитуриентов, выпускников, пользователей и цифровые пропуска без потери данных и без одномоментного переписывания существующих модулей.

PERSON-001 является foundation-этапом: старые таблицы и API остаются рабочими, а `person_id` добавляется как nullable-связь.

## Таблица people

Основные поля:

- ФИО: `last_name`, `first_name`, `middle_name`;
- дата рождения: `birth_date`;
- общие атрибуты: `gender`, `citizenship`, `status`;
- контакты: `phone`, `email`;
- фото: `photo_path`;
- идентификаторы: `snils`, `inn`.

`photo_path` в `people` становится предпочтительным общим источником фото. Старые `photo_path` в `students`, `teachers`, `graduates` остаются fallback на переходный период.

## Связанные профили

Один Person может иметь несколько профилей одновременно:

- `Student`;
- `Teacher`;
- `ApplicantApplication`;
- `Graduate`;
- `User`;
- `DigitalIdentity`.

Пример: преподаватель может быть выпускником колледжа, сотрудник может иметь учетную запись пользователя, студент может стать выпускником и сохранить тот же Person.

## Миграция без потери данных

PERSON-001 не удаляет старые поля ФИО, телефона, email и фото из профильных таблиц. Добавлены nullable `person_id` в:

- `students`;
- `teachers`;
- `applicant_applications`;
- `graduates`;
- `digital_identities`.

В `users` поле `person_id` уже было подготовлено ранее и продолжает использоваться.

## PersonService

`PersonService` отвечает за:

- создание Person;
- поиск возможных дублей;
- привязку существующего профиля;
- обновление общих данных;
- получение связанных профилей.

Автоматическое объединение только по ФИО запрещено. Для поиска кандидатов используются:

- СНИЛС;
- email;
- телефон;
- ФИО + дата рождения.

Если найдено больше одного кандидата, запись считается неоднозначной и не связывается автоматически.

## Команда связывания

Команда:

```bash
php artisan person:link-existing --dry-run
php artisan person:link-existing --apply
```

`--dry-run` показывает план без изменения БД.

`--apply` создает Person и заполняет `person_id` только для однозначных случаев.

Выпускник связывается с Person своего студента, если студент уже связан.

## API

Read-only foundation API:

- `GET /api/people`;
- `GET /api/people/{id}`;
- `GET /api/people/{id}/profiles`.

Доступ: `people.view`.

## Frontend

Маршрут:

- `/people`.

Интерфейс показывает:

- ФИО;
- фото;
- контакты;
- статусы;
- связанные профили;
- цифровые пропуска;
- быстрые переходы к существующим карточкам.

## RBAC

Добавлены permissions:

- `people.view`;
- `people.create`;
- `people.update`;
- `people.link`;
- `people.merge`.

На этапе PERSON-001 реализован только read-only UI и безопасное связывание через command. Merge зарезервирован для будущего этапа.

## Обратная совместимость

Старые API студентов, преподавателей, заявлений, выпускников и цифровых пропусков сохраняют прежние поля и поведение. Новое поле `person_id` добавлено как дополнительное, не обязательное.

## Использование в импорте ФИС

Импорт заявлений ФИС сопоставляет абитуриентов с `Person` по СНИЛС, существующему заявлению и ФИО + дате рождения. Один `Person` может иметь несколько заявлений. Неоднозначные совпадения отправляются на ручную проверку.

## HR-001A: Employee как профиль Person

Добавлен кадровый профиль `Employee`. Person остается источником общей личности, фотографии и контактов. Employee хранит табельный номер, кадровый статус, назначение, ставку и связь с Department/Position. Один Person может одновременно иметь профили Teacher и Employee.

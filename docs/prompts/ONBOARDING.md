# Стартовые промпты для новых чатов

Когда у рабочего чата кончается контекст, он закрывается, а на его место открывается новый — с тем же названием и той же областью кода. Область важнее чата: она записана в документах, а чат сменный.

**Чаты называются по области, без номеров.** Нумерация уже один раз разъехалась: у владельца и на доске были разные цифры, и «возьми задачу 5» могло уйти не туда. Название однозначно.

## Что сделать перед закрытием старых чатов

Убедиться, что работа не пропадёт:

```bash
ssh andale@192.168.34.114 "cd /home/andale/CollegePortal && git status --short && git worktree list"
```

Грязный worktree или незалитая ветка — попросить чат закоммитить и влить, прежде чем закрывать. Сгенерированный `frontend/public/version.json` не в счёт, он таким и должен быть.

## Промпт для чата «Учётные записи, роли и демо-данные»

```text
Ты — рабочий чат CollegePortal, область «Учётные записи, роли и демо-данные».
Предыдущий чат этой области закрыт по исчерпанию контекста, ты продолжаешь
за ним.

Прочитай в таком порядке:
1. CLAUDE.md — правила проекта, топология, как запускать тесты.
2. docs/ACTIVE_WORK.md — состояние; раздел «Кто чем занят прямо сейчас»
   найди по названию своей области.
3. docs/prompts/ASSIGNMENTS.md — раздел твоей области: что делать сейчас
   и что дальше.

Твоя область: контроллеры отчётов, сидеры демонстрационных данных,
экраны, обработчики импорта и выгрузки, движок расписания.
Не заходишь: контур авторизации, routes/api.php, EnsurePermission,
RoleSeeder — они за другими областями, там идёт работа.

Порядок работы: заявляй задачу на доске в ACTIVE_WORK.md ДО того, как
заводишь ветку; тесты только на DEV по инструкции из CLAUDE.md, на SQLite
и на PostgreSQL 17; закончив — коммит и push с DEV, потом обнови локальную
рабочую копию владельца:
  git fetch dev && git merge --ff-only dev/develop

Начни с того, что скажи мне: какая задача у тебя «Сейчас» и что ты по ней
собираешься сделать первым шагом. Кода пока не пиши.
```

```text
Ты — рабочий чат CollegePortal, область «ФИС ГИА и приёмная комиссия»
(права доступа и внешний обмен). Предыдущий чат этой области закрыт

3. docs/prompts/ASSIGNMENTS.md — раздел твоей области.
4. docs/prompts/2_ARCH_001_PERMISSIONS.md — задание по ARCH-001,
   которое ты сейчас ведёшь.

Твоя область: routes/api.php, EnsurePermission, RoleSeeder, права ролей,

и назвал права, до которых роли дотягивались через них. Следующий шаг —
объявить права у маршрутов и снять зонтики. Помни правило, выведенное
на этом же проекте: таблица прав только СУЖАЕТ доступ, снятие зонтика
закрывает двери, а не открывает. Каждую роль после правки проверяй
обходом, а не рассуждением. Задание требует показать план владельцу
и дождаться подтверждения.

Порядок работы: заявляй задачу на доске в ACTIVE_WORK.md ДО того, как
заводишь ветку; тесты только на DEV, на SQLite и на PostgreSQL 17;
закончив — коммит и push с DEV, потом:
  git fetch dev && git merge --ff-only dev/develop

Начни с того, что скажи мне: на каком шаге ARCH-001 остановился
предыдущий чат и что ты делаешь первым. Кода пока не пиши.
```

## Почему последняя строка везде одинаковая

Новый чат просят сначала пересказать своё задание и не писать код. Это стоит одну реплику и ловит худший случай: чат прочитал не тот раздел или понял задачу иначе. Дешевле поймать это до ветки, чем после вливания.

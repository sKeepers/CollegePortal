# Назначения по чатам

**Обновлено: 10.08.2026.**

Этот файл ведёт координирующий чат по указанию владельца. Рабочие чаты его **читают, но не правят** — иначе назначения и отчёт о них перемешаются.

Соседний раздел «Кто чем занят прямо сейчас» в [ACTIVE_WORK.md](../ACTIVE_WORK.md) — наоборот: там пишут рабочие чаты о себе. Два файла, две стороны разговора, конфликтов по строкам нет.

## Как пользоваться

1. **Сначала обнови ствол**, иначе прочитаешь вчерашнее:
   ```bash
   git fetch dev && git merge --ff-only dev/develop
   ```
2. **Найди свой раздел** по названию, которым ты сам записан на доске в `ACTIVE_WORK.md`. **Не по номеру:** нумерация чатов разъехалась, у владельца и на доске она разная. Название — единственный надёжный признак.
3. Делай то, что в разделе «Сейчас». Закончив — переходи к «Дальше по очереди», не спрашивая.
4. **Отметься на доске** в `ACTIVE_WORK.md`: начал — допиши строку, закончил — убери.
5. Если назначение устарело — задача уже сделана, файл занят другим, условие не выполняется — **не выдумывай замену и не бери чужое.** Напиши владельцу, что именно разошлось.

Если своего раздела не нашёл — значит ты новый чат. Не бери ничего из чужих разделов, скажи владельцу.

## Чат «ФИС ГИА и приёмная комиссия»

**Область:** права доступа и внешний обмен. Владеет `EnsurePermission::DOMAIN_RULES` и `RoleSeeder`.

**Сейчас:** конкурсы ФИС — `CompetitiveGroupUID` из `InstitutionExport`.

**Заодно, владелец подтвердил 10.08.2026.** Роль `study_records` получает `403` на специальностях и образовательных программах, хотя ведёт группы и выпуск. Право `reference.view` у неё **уже есть** — `BUG-010` раздал его всем ролям через `BASELINE_PERMISSIONS`. Осталось развести чтение и правку для двух префиксов в `EnsurePermission::DOMAIN_RULES`, как уже сделано для `api/admin/reference`:

```php
'api/education-programs' => ['reference.view', 'reference.manage', 'reference.manage', 'reference.manage'],
'api/specialties'        => ['reference.view', 'reference.manage', 'reference.manage', 'reference.manage'],
```

Правка справочников остаётся у владельца справочников — меняется только чтение. Помни своё же правило: **таблица только сужает доступ**, проверь, кому этим не закрыл дверь.

**Дальше по очереди:** [5_ARCH_001_PERMISSIONS.md](5_ARCH_001_PERMISSIONS.md) — `ARCH-001`, одна правда о правах вместо трёх списков.

Она отдана тебе **не по очереди, а по владению**: живёт ровно в тех файлах, которыми ты уже управляешь. Требует показать план до правки кода.

**Не заходить:** `AccessReportController`, сидеры демо-данных — за чатом «Учётные записи и демо-данные». `AppServiceProvider`, `bootstrap/app.php` — за чатом «Единая карточка человека».

## Жёсткие запреты на одновременный запуск

- `ARCH-001` — только после того, как `BUG-010` влит. Оба переписывают таблицу прав.
- `SEC-006` и `SEC-002` — последовательно и одним чатом: обе трогают порядок middleware.
- `SEC-002` и `ARCH-001` — не одновременно: обе про контур авторизации, и обе при ошибке либо разлогинивают всех, либо закрывают людям доступ.

# Промпты для отдельных чатов

Крупные задачи запускаются отдельными чатами: у каждой свой контекст, и мешать их в одну сессию дорого и вредно для качества.

В каждом файле текст готов к копированию целиком. Решения, уже принятые владельцем, в промптах записаны — чтобы новый чат не спрашивал заново и не решал иначе.

| Файл | Задача | Состояние |
| --- | --- | --- |
| [TASK_PERSON_DOCUMENTS.md](TASK_PERSON_DOCUMENTS.md) | Документы на уровень `Person`, полнота карточки студента | одобрено, следующая по приоритету |
| [TASK_EXPORT_IMPORT_SYMMETRY.md](TASK_EXPORT_IMPORT_SYMMETRY.md) | Свести экспорт и импорт по всем реестрам, экспорт расписания, полнота карточек педагогов и сотрудников | одобрено |
| [TASK_SEC_002_COOKIE.md](TASK_SEC_002_COOKIE.md) | `SEC-002`: токен в httpOnly cookie с CSRF | подход выбран, срок не назначен |
| [TASK_ARCH_001_PERMISSIONS.md](TASK_ARCH_001_PERMISSIONS.md) | `ARCH-001`: право объявляется у маршрута, а не выводится из URL | не обсуждалось со владельцем |
| [../PORTAL_AUDIT_PROMPT.md](../PORTAL_AUDIT_PROMPT.md) | Аудит портала: поиск дефектов без исправления | можно запускать в любой момент |

## Порядок

`TASK_PERSON_DOCUMENTS` первым: пока он не сделан, паспорт и документ об образовании невозможно завести студенту, не прошедшему приёмную комиссию.

Аудит можно запускать параллельно с чем угодно: он ничего не меняет.

`TASK_SEC_002_COOKIE` и `TASK_ARCH_001_PERMISSIONS` требуют плана до реализации — оба затрагивают систему целиком, и оба разлогинивают или закрывают доступ при ошибке. Одновременно их не запускать: они пересекаются в контуре авторизации.

## Что ждёт не разработки, а доступов

- **ФИС ГИА:** адрес тестового контура, сертификат, учётные данные.
- **SMTP:** пароль ящика `portal@skki.ru` на `smtp.mail.ru`. Через Beget не пройдёт SPF: у домена `v=spf1 redirect=_spf.mail.ru`.

Пока их нет, `SoapFisTransport` остаётся заглушкой, а восстановление пароля не работает.

В разделе «5. Приложение» отчёта лежат тесты, которыми находки подтверждались. Используй их как отправную точку: часть можно внести в набор почти как есть. Тест, обходящий все роли и все разделы, там тоже есть — но вносить его в CI следует вместе с задачей 4, а не здесь.

## Грабли

- **Новый маршрут вноси в таблицу прав** в `EnsurePermission`: при промахе молча возвращается `reference.manage`. Это и есть находка 8.
- **Порядок маршрутов:** литеральный сегмент раньше параметрического.
- **BOM снимай до разбора CSV, а не после.**
- Не заводи второй расчёт там, где сервис уже есть: расчёт полноты карточки живёт в `AdmissionDocumentReadinessService`.

## Проверки

Тесты на DEV в отдельном worktree, ветка от `origin/develop`, прогон на SQLite и на PostgreSQL 17. Каждую закрытую находку покрывай тестом, воспроизводящим её, — иначе она вернётся.

Находку 6 после исправления проверь **в браузере на DEV**, а не только тестом: она про экран, которого нет.

## Когда закончишь

Коммить и пушить с DEV, отметить закрытые находки в `docs/AUDIT_2026-08-08.md`, обновить `docs/ACTIVE_WORK.md`, затем **обновить локальную рабочую копию** — владелец читает код в ней:

```bash
git fetch dev && git merge --ff-only dev/develop
```

На PROD ничего не разворачивать без отдельного поручения.

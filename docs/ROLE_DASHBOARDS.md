# Role Dashboards

## Назначение

Role-based Dashboards дают пользователю рабочий стол, соответствующий его основной роли. Цель Phase 1 — не заменить все разделы, а убрать лишние виджеты с главной страницы и показать только то, что нужно роли в начале рабочего дня.

## Поддерживаемые роли Phase 1

- `admin` — административный Dashboard.
- `director` — административный Dashboard директора.
- `teacher` — преподавательский Dashboard.
- остальные роли — общий Dashboard, сохраненный как fallback.

Если у пользователя несколько ролей, frontend использует primary role из `auth.user.role.code`. Это соответствует текущему API авторизации.

## Dashboard администратора и директора

Показывает:

- количество студентов;
- количество преподавателей;
- занятия сегодня;
- людей сейчас в здании;
- опоздания, если такие данные есть в сводке проходной;
- отказанные проходы;
- новые заявления;
- пакеты ФРДО/ФИС с ошибками;
- последние события аудита;
- быстрые действия: Студенты, Приемная комиссия, Расписание, Проходная, ФРДО, ФИС, Аудит.

Источники данных:

- `students`;
- `teachers`;
- `schedule-lessons`;
- `access/reports/summary`;
- `access/reports/events`;
- `applicant-applications`;
- `frdo-packages`;
- `fis-packages`;
- `admin/audit`.

## Dashboard преподавателя

Показывает:

- мои занятия сегодня;
- ближайшее занятие;
- мои группы;
- моя нагрузка;
- открытые журналы в виде связанных занятий;
- ближайшие экзамены;
- быстрые действия: Мое расписание, Журнал, Нагрузка, Экзамены, Мой QR-пропуск.

Связь пользователя с преподавателем определяется по `person_type=teacher` и `person_id`, если эти поля есть у пользователя. Если связь отсутствует, frontend пытается найти преподавателя по email. Если преподаватель не найден, показывается преподавательский Dashboard с понятным предупреждением и без ошибки интерфейса.

## Общий Dashboard

Все остальные роли пока получают прежний общий Dashboard:

- студенты;
- группы;
- преподаватели;
- занятия сегодня;
- быстрые действия общего рабочего места;
- общие задачи, уведомления и последние события.

## Как добавить новый ролевой Dashboard

1. Создать компонент в `frontend/src/pages/dashboard/role/`.
2. Подключить компонент в `DashboardPage.vue`.
3. Добавить условие выбора по primary role.
4. Использовать существующие API или read-only агрегирующие endpoints.
5. Не показывать пользователю виджеты, не относящиеся к его роли.
6. Обновить этот документ и `TASKS.md`.
7. Проверить `php artisan test`, `npm run build` и вход под тестовым пользователем нужной роли.

## Ограничения Phase 1

- Персональная связь teacher-user зависит от заполнения `person_type/person_id` или совпадения email.
- Для ролей `study`, `admission`, `student`, `security` отдельные Dashboards пока не реализованы.
- Часть показателей, например опоздания, отображается только если backend уже возвращает их в существующей сводке.

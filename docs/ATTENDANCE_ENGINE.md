# Attendance Analysis Engine

## Назначение

Attendance Analysis Engine сопоставляет события проходной с расписанием и показывает оперативную картину присутствия преподавателей и студентов за текущий день.

Модуль ничего не изменяет в существующих процессах проходной, расписания или журнала. На этапе ATTENDANCE-001A это read-only аналитика поверх уже имеющихся данных.

## Источники данных

Используются существующие сущности:

- `access_events` — события входа/выхода через проходную;
- `digital_identities` — связь QR-пропуска с владельцем;
- `schedule_lessons` — расписание занятий;
- `teaching_loads` и `teaching_load_items` — контекст нагрузки преподавателя;
- `students` и `groups` — активные студенты и их группы;
- `teachers` — преподаватели;
- `settings` — текущий учебный год и базовые настройки времени.

Новые таблицы не создавались.

## Backend

Сервис:

- `App\Services\AttendanceAnalysisService`

API:

- `GET /api/attendance/teachers/today`
- `GET /api/attendance/students/today`

Оба endpoint доступны пользователям с правом `view_reports`.

## Логика для преподавателей

Для каждого преподавателя вычисляется:

- статус: `not_arrived`, `entered`, `late`, `early`, `present`, `arrived`, `no_schedule`;
- первый вход за день;
- последний выход за день;
- текущие присутствие в здании;
- первая пара по расписанию;
- опоздание в минутах;
- краткий комментарий.

Если первая пара есть, но входа нет, преподаватель считается не пришедшим. Если вход позже начала первой пары, статус — опоздал. Если вход раньше начала первой пары, статус — пришел заранее.

## Логика для студентов

Для каждого активного студента вычисляется:

- статус: `not_entered`, `entered`, `late`, `early`, `present`, `arrived`, `no_schedule`;
- первый вход за день;
- последний выход за день;
- текущие присутствие в здании;
- первая пара группы;
- опоздание в минутах;
- краткий комментарий.

Студент сопоставляется с расписанием через свою группу.

## Frontend

Страница:

- `/attendance`

Интерфейс показывает таблицу с режимами:

- Преподаватели;
- Студенты.

Колонки:

- ФИО;
- статус;
- первый вход;
- последний выход;
- первая пара;
- опоздание;
- комментарий.

## Ограничения MVP

- Анализ выполняется только за текущий день.
- Нет ручной корректировки статусов.
- Нет учета уважительных причин отсутствия.
- Нет отдельных правил допустимого опоздания по группам или ролям.
- Нет сохранения рассчитанных результатов в БД.
- Аналитика зависит от полноты расписания и корректности событий проходной.

## Будущие этапы

- Отчеты за период.
- Настраиваемое окно допустимого опоздания.
- Учет уважительных причин.
- Сводки для Dashboard.
- Уведомления учебной части и кураторов.
- Сравнение проходной, журнала и расписания.

## ATTENDANCE-001B: Dashboard и детализация

В ATTENDANCE-001B аналитика посещаемости интегрирована в Dashboard руководителя.

Добавлены показатели:

Преподаватели сегодня:

- вовремя;
- опоздали;
- не пришли;
- сейчас в здании.

Студенты сегодня:

- вошли;
- опоздали;
- не вошли;
- сейчас в здании.

Блок “Что требует внимания” использует результаты `AttendanceAnalysisService` и показывает:

- преподавателей, не пришедших к первой паре;
- преподавателей с опозданием;
- студентов с опозданием больше порога;
- расписание без входа через проходную.

Страница `/attendance` поддерживает фильтры:

- тип: преподаватели / студенты;
- статус;
- группа;
- преподаватель;
- период.

Поддерживаются прямые ссылки:

- `/attendance?type=teachers&status=late`;
- `/attendance?type=teachers&status=absent`;
- `/attendance?type=students&status=late`;
- `/attendance?type=students&status=absent`.

Правая карточка выбранной записи показывает ФИО, фото, роль, первую пару, первый вход, опоздание, последний выход, время внутри, текущий статус и быстрые ссылки.

Настройки порогов:

- `attendance.teacher_late_threshold_minutes` — по умолчанию 5 минут;
- `attendance.student_late_threshold_minutes` — по умолчанию 10 минут.

Пороги используются для управленческого блока “Требует внимания”. Сам факт опоздания фиксируется при любом входе позже начала первой пары.

## ATTENDANCE-001C: История присутствия и учет времени

Добавлена историческая аналитика за выбранный период. Аналитика остается read-only: сервис читает `access_events`, `schedule_lessons`, `students`, `teachers` и настройки времени, но не изменяет проходную, расписание или журнал.

### API истории

- `GET /api/attendance/history` — сводный отчет за период;
- `GET /api/attendance/history?export=csv` — CSV-выгрузка сводного отчета;
- `GET /api/attendance/person/{type}/{id}/summary` — сводка по человеку;
- `GET /api/attendance/person/{type}/{id}/days` — детализация по дням.

Параметры:

- `date_from`, `date_to`;
- `type`: `teacher` или `student`;
- `person_id`;
- `group_id`;
- `teacher_id`;
- `status`.

### Правила расчета времени внутри

- учитываются только события `access_events.result = allowed`;
- события сортируются по времени;
- присутствие считается парами `IN -> OUT`;
- несколько пар за день суммируются;
- отказанные проходы не увеличивают время внутри;
- `OUT` без предыдущего `IN` учитывается как unmatched exit, но не дает времени внутри;
- `IN` без `OUT` помечается как незакрытая сессия, время выхода не выдумывается;
- переход через полночь поддерживается, если `OUT` попадает в окно `attendance.max_open_session_hours`;
- открытая сессия не получает расчетное время до `now`, чтобы не искажать исторический отчет.

### Сопоставление с расписанием

Для преподавателя план берется из его занятий. Для студента план берется из расписания группы.

- опоздание: первый вход позже начала первой пары;
- ранний уход: последний выход раньше окончания последней пары минимум на `attendance.early_leave_threshold_minutes`;
- отсутствие: есть расписание, но нет входа;
- день без расписания: занятий нет, отсутствие не фиксируется.

### Frontend

Страница `/attendance` получила режимы:

- `Сегодня` — оперативная аналитика 001A/001B;
- `Период` — сводная таблица за выбранные даты;
- `По человеку` — та же сводка с детализацией выбранной записи.

Историческая таблица показывает: ФИО, дней по расписанию, присутствовал, отсутствовал, опозданий, ранних уходов, всего времени внутри и среднее время в день.

Карточка человека содержит вкладки:

- Сводка;
- По дням;
- Проходы;
- Расписание.

Во вкладке “По дням” используется простая CSS-полоса времени без сторонних библиотек: плановое время и фактическое присутствие показываются отдельными сегментами.

### Настройки

Добавлены настройки:

- `attendance.early_leave_threshold_minutes` — порог раннего ухода, по умолчанию 10 минут;
- `attendance.max_open_session_hours` — окно поиска выхода после входа, по умолчанию 16 часов.
